  - 用户需求：现有构建流程是自上而下（目标→规则→卷→大纲→正文），需要另一种自下而上的模式——剧情推演模拟器：在场人物进入实时模拟状态，可指定人物记录其行为过程和事件链作为剧情脚本用于生成正文；人物增加扩展属性与作品级欲望定义，行为在不同属性与欲望下产生；另需一个系统层面 skill 构建这些定义，使数值架构合理、运行时能涌现内容。先出设计文档。
  - **产出**：`docs/剧情推演模拟器设计.md`（设计稿，15 节）。核心架构：**数值节拍 + LLM 叙事化混合引擎**——作品级 `SimPlaySchema`（属性/欲望/行为定义）+ 本地 seeded 节拍引擎（每 tick 感知→欲望演化→效用决策→执行→事件，纯本地零 API、mulberry32 可复现）+ LLM 低频批量叙事化（8-12 事件段一次调用，单向不回写数值）+ `PlotScript` 剧情脚本库（指定主视角人物的可见事件链，作品级库+章节槽位 `plotScriptIds` 镜像写作技能模式）+ 正文生成注入【剧情脚本】既定事件块。
  - **系统级技能「数值架构师」**：不进用户写作技能库（nc2-writing-skills-v1 无内置条目是刻意设计），形态照 `memoryTemplates` 先例（内置规范 + 【推演设计】协议块 + 本地 `validateSchema` 校验器 + 草稿-确认制落地），内置 8 条数值设计准则（欲望冲突对/每欲望双满足行为/阈值错拍/保底行为/互动传播等）。
