## 0. 结论摘要

目标是把创作台从「一张全局画布 + 章节文本」升级为：

1. **卷 → 独立画布**：每卷一张工作画布，标签切换；
2. **人物 → 状态版本**：状态0、状态1、状态2……，名字/性别稳定，属性随状态变化；
3. **章节 → 区域 + 名单快照**：在画布上画出本章浅色区域，区域内人物组成本章名单；人物分「在场」与「仅提及」，每人引用一个状态；
4. **生成 → 只认快照**：章节大纲/正文生成只使用本章快照，不在名单内的人物不得自行编造；
5. **切章 → 自动读快照**：切换章节大纲或正文时自动加载本章快照，并与画布章节视图保持一致；
6. **跨卷 → 复制/镜像/剪切**：人物/环境跨卷复制时保留身份 ID，状态一起复制，供章节快照继续引用；
7. **编辑 Agent → 同步驾驭**：编辑 Agent 必须能看见卷/状态/快照，并能创建人物默认状态、新建状态、修改指定状态、切换状态；不能等数据结构做完再补。

核心原则：

> **区域负责取人，场景自动记录，名单负责锁人，状态负责锁属性；切章先写回当前场景，再还原目标章人物位置/父环境/状态。**  
> **每增加一个结构维度，必须同时增加编辑 Agent 的「看得见、表达得出、安全落地、可测试」四项能力。**

### 0.2 已确认产品决定（2026-10-24）

1. **名单外人物**：允许无名背景群演；不得新增具名人物，群演不得拥有姓名、独立台词或推动剧情。已写入大纲/正文生成与编辑 Agent 的硬规则。
2. **章节模式画布**：**不做**节点变暗、冻结场景渲染或 `canvasMode` 切换。只保留现有「当前章节区域高亮」；切章共享 `activeChapterId` 与章节快照上下文。R6 因此缩减为章节上下文、名单/快照面板与切章读取。
3. **被快照引用的状态**：**不强制锁定**。允许原地修改/删除，但 UI 与编辑 Agent 必须在操作前明确提示影响的章节；不要求复制新状态，也不保留历史版本——快照只记录 `stateId` 与位置，状态内容改了，重新生成就用新内容。
4. **章节场景自动同步（2026-10-25 用户确认）**：名单由章节区域内人物自动派生；离开/切换章节时把当前章场景写回快照，切回时还原人物位置、父环境与当前状态。首次进入无快照的章节不强行移动人物，直接以当前画布为底稿记录。环境布局视为固定，不做快照、不还原环境几何。自动同步只改内存，只有手动「保存」/Ctrl+S 才写 localStorage。

## 1. 需求基线（对话中已确认）

### 1.1 人物状态

- 人物有一个隐藏基础 ID；当前可直接使用 `node.id`。
- 顶层固定：**人名、性别**，不随状态变化。
- 状态是数组结构，第一个是「默认状态」。
- 每个状态包含：人物形象（一张大图 + 从大图裁出的圆形头像）、年龄（建议）、基础信息、身份信息、关系信息。
- 新建状态基本是复制上一个状态的全部信息，再修改需要变化的字段。
- 章节快照只指向 `stateId`，不复制属性。

### 1.2 章节区域与快照

- 在画布上手动拖出一个浅色矩形区域，左上角有文字标签（如“第一章”）。
- **只有区域里的人物节点**进入快照。
- 在场人物放在建筑/房间环境里；对白提及但不出场的人物放在区域边缘。
- 快照记录区域内人物 + 每个人的位置、父环境与当前状态。
- 名单锁定：本章只有名单中的人出场；对白中提到的其他人也要在名单里。
- **名单不需要手动采集**：区域内人物自动派生；角色按中心点/边缘带自动建议。旧的手动增删/改角色/选状态入口已移除。
- 场景（位置/父环境/状态）随画布自动记录，切章自动还原。

### 1.3 切章

- 切换章节时：先把当前章场景写回快照 → 切到目标章画布 → 回放目标章快照（只移动快照内人物）。
- 快照外的人物保持原位，不参与回放。
- 首次进入没有快照的章节不移动人物，直接把当前画布记为本章底稿。

### 1.4 卷画布与复制

- 每一卷对应一张独立画布，通过标签切换。
- 提供人物/环境节点的镜像复制、剪切能力，用于跨卷搬运。

### 1.5 编辑 Agent 同步（横切要求）

- 编辑 Agent 必须知道当前有几卷、正在哪张画布上工作，以及目标操作属于哪一卷。
- 编辑 Agent 必须知道人物是「顶层身份 + 多个状态」：名字/性别不随状态变，属性属于状态。
- 编辑 Agent 必须能：创建人物（自动带默认状态）、新建状态（复制来源状态后改字段）、修改指定状态、切换当前状态、重命名状态；删除状态需保护引用。
- 编辑 Agent 必须知道本章快照的在场/仅提及名单与引用状态；不能把「仅提及」说成在场，也不能自行编造名单外具名人物。
- 这些能力与对应数据结构**同一个切片开发、同一个切片验收**，不允许先改结构、后补编辑能力。

| 名词 | 含义 |
|---|---|
| 工作画布 | 当前可直接编辑的画布，代表“当前/最新世界状态” |

| 状态锁 | 快照引用的状态在后续是否允许被原地修改 |

## 3. 现状约束（已核对代码）

设计初期核对到的约束如下；第 1、2、8、9 项已随 V1/S1–S3 解决，保留在此说明演进背景：

1. **多画布（已解决）**：`studioStore` 现以 `boards + activeBoardId` 为权威数据，节点归属仍靠 `parentId`，ID 稳定。见 `src/stores/studioStore.ts`。
2. **人物多状态（已解决）**：`CharacterData` 现为顶层 `name/gender` + `states[]` + `activeStateId`；属性通过解析函数读取。见 `src/types/sim.ts`、`src/stores/characterStates.ts`。
3. **章节无快照（区域已解决）**：R1 已把区域存到 `SimBoard.regions`，但 `SimChapter` 仍只有 `id/title/volumeId/requirement/outline/content`，没有名单/快照。见 `src/types/sim.ts`、`src/stores/chapterRegions.ts`。
4. **章节生成读全局画布摘要**：`genChapterOutline` / `genChapterContent` 使用 `simCanvasSummary()`，默认只保留约 900 字符；画布越大，本章相关人物越容易被截掉。见 `src/engines/studioEngine.ts`（`simCanvasSummary`、`buildChapterSystem`）。
5. **编辑室按当前画布按需检索**：`canvasLookupBlock` 是编辑室用的按名检索；章节生成暂未接快照。
6. **章节选择已共享（R1 解决）**：`uiStore.activeChapterId` 由大纲面板、正文面板、顶栏与画布区域共用，`useActiveChapterId()` 负责无效值回落首章；R6 的切章自动读快照可直接挂在这个上下文上。
7. **持久化是全量 localStorage**：`persist` 没有 `partialize`；大纲流式生成约每 400ms 写一次 store，每次都会序列化整个状态。多卷画布和大量数据前必须先做持久化节流/拆分。见 `src/stores/studioStore.ts`（`persist(...)`）。
8. **存档（已解决多画布）**：`src/services/studioSync.ts` 现在保存/载入全部 `boards`，旧单画布存档仍按同一规则迁移；未来快照数据需要再扩存档格式。
9. **人物形象按状态存储（已解决，v2.31 重构）**：每个状态一张人物形象大图（`charimg:<nodeId>:<stateId>:<nonce>`）与可选头像（`charhead:<nodeId>:<stateId>:<nonce>`），图片本体存浏览器 IndexedDB，状态里只存元数据（尺寸/预设/crop）。换图/重裁总是写新 key（copy-on-write）；跨卷镜像共享 key，复制为新逐状态重写 key 并复制图片。旧 `avatar` 素材 ID 与 `portraitKey` 写真不迁移、不做特判。见 `src/services/characterImages.ts`、`src/stores/characterStates.ts`、`src/stores/boardCopy.ts`。
10. **存档不含图片字节**：形象/头像只在本机 IndexedDB；换机/清浏览器数据会丢，属性面板会提示“形象文件缺失”，画布回落性别剪影。这是现有约束，不随本次改动解决。

## 4. 目标与非目标

### 4.1 本期目标（可分批实现）

- 人物状态版本与状态切换；
- 章节区域绘制、绑定章节、标签；
- 本章名单：区域内人物自动派生，按在场/仅提及分组、引用状态；

- 编辑 Agent 同步掌握卷、状态、快照，并能安全落地状态操作。

### 4.2 明确不做（至少第一版不做）

- 完整画布时间旅行：切章只还原快照内人物的位置/父环境/状态，不还原属性内容、不还原环境几何、不冻结整张画布；
- 每章一份完整画布副本；
- 快照保存状态内容的历史版本：状态内容改了，重新生成即使用新内容；
- 状态完整 revision 历史（除非后续确认需要“严格不可变”）；
- 一章多场景的结构化 `scenes[]`（数据模型预留，UI 第一版按一章一个区域）；
- 跨卷实时联动镜像（改 A 卷同步 B 卷）；只做复制/剪切后独立演化；
- 跨设备图片同步；
- 编辑 Agent 直接改章节快照/名单/区域、自动跨卷复制/剪切、或自动改写被快照引用的状态（章节场景由系统随画布自动同步，Agent 只改工作画布）。

## 5. 数据模型（提案）

> 所有新字段均为可选；旧数据通过 sanitize 迁移，缺失时回退到现有行为。

### 5.1 人物状态（已实现）

```ts
type CharacterImagePreset = '1:1' | '4:3' | '16:9' | '9:16';

interface CharacterImageCrop {
  x: number;                    // 源图像素坐标
  y: number;
  size: number;                 // 正方形边长（源图像素）
}

interface CharacterStateImage {
  key: string;                  // charimg:<nodeId>:<stateId>:<nonce>
  width: number;                // 大图实际像素
  height: number;
  preset: CharacterImagePreset | 'original'; // AI 预设；上传为 original
  headKey?: string;             // charhead:<nodeId>:<stateId>:<nonce>（256×256）
  crop?: CharacterImageCrop;    // 仅在 headKey 存在时保留
}

interface CharacterState {
  id: string;                   // 状态 ID，稳定；复制人物时保留
  label: string;                // 状态0 / 状态1 / 状态2 / 重伤后……
  age?: number;                 // 年龄会随剧情变化，放状态里
  basicInfo: string;            // 基础信息
  identityInfo: string;         // 身份信息
  relations?: string;           // 关系信息
  image?: CharacterStateImage;  // 人物形象（大图 + 头像），按状态独立
}

interface CharacterData {
  kind: 'character';
  // node.id 作为隐藏基础 ID，cross-board 复制/镜像时保留；不新增重复 ID 字段
  name: string;               // 顶层：人名，跨状态稳定
  gender: CharacterGender;    // 顶层：性别，跨状态稳定
  states: CharacterState[];   // 至少一个；states[0] 为「状态0」，不可删、可改名
  activeStateId: string;      // 工作画布当前显示/编辑的状态；非法值回落 states[0]
}
```

约定：

- 旧数据迁移：`sanitizeCharacterData(raw, nodeId)` 只在没有有效 `states` 时，把旧平铺 `age/basicInfo/identityInfo/relations`（及旧 `desc`）灌入状态0；已有 states 只清洗不覆盖，因此 reload 不会重置状态。**v2.31 起旧 `avatar` / `portraitKey` 一律丢弃，不迁移图片字节，也不删除旧 IDB 字节（可能成为孤儿，避免误删）。**
- 默认状态：迁移状态 ID 固定 `state0`，标签「状态0」；新建状态 ID 用 uid，标签建议「状态1、状态2…」，可重命名。标签在人物内唯一。
- 新建状态：复制「基于」状态（默认=当前状态）的全部字段，包括整个 `image` 对象（继承大图/头像引用）；创建后设为当前状态。之后换图/重裁总是写新 key，不会原地覆盖被继承的图片。
- 形象清洗：`sanitizeCharacterImage` 只接受合法 `charimg:`/`charhead:` key、1–20000 的整数尺寸、四种预设或 `original`；crop 仅在 headKey 存在时保留并夹在图像范围内；任何关键字段损坏则整张图当作无图。
- 写入口拆分：`updateCharacter` 只写 `name/gender`；状态属性走 `updateCharacterState` / `updateActiveCharacterState`。新增/更新/切换/重命名/删除返回结构化结果，错误码 `not-found | base-not-found | empty-label | duplicate-label | protected | last-state`。
- 删除：首项（状态0）与最后一个状态不可删；删除当前状态时 `activeStateId` 回退首项。
- 所有读取人物属性的代码必须经过解析函数，不能直接读 `data.basicInfo` 等平铺字段。

解析与 key 辅助函数（`src/stores/characterStates.ts`）：

```ts
characterStateOf(data, stateId?) // 指定状态；缺省 activeStateId；找不到回退 states[0]
activeCharacterState(data)       // 工作画布显示用
newCharacterImageKey(nodeId, stateId) // charimg:<nodeId>:<stateId>:<nonce>
newCharacterHeadKey(nodeId, stateId)  // charhead:<nodeId>:<stateId>:<nonce>
collectStateImageKeys(state)     // 该状态引用的大图/头像 key
sanitizeCharacterImage(value)    // 形象元数据清洗
```

### 5.2 章节区域

```ts
interface ChapterRegion {
  id: string;
  chapterId: string;          // 绑定的章节
  x: number;                  // 画布绝对坐标
  y: number;
  width: number;
  height: number;
  color?: string;             // 预留；R1 统一使用主题色
}
```

- 区域是画布注释对象，不进入人物/环境节点数组，不参与 AI 摘要、按需检索、属性面板、MiniMap 或跨卷节点复制。
- 存储位置：`SimBoard.regions`（R1 已实现）。归属画布由章节 `volumeId` 解析：未分卷/未知卷/卷画布缺失 → `main`，合法卷 → `vol:<volumeId>`；一章在所属画布上最多一个区域。
- **实现（R1，2026-10-24）**：`ChapterRegionsOverlay` 用 `useViewport()` 把画布坐标换算成屏幕矩形（`left = x*zoom + vp.x`）渲染，只让 24px 标签条与四角手柄接收鼠标事件，区域主体 `pointer-events:none`，因此不挡节点点击/拖拽；边框、标签、手柄不随缩放变细。绘制/移动/缩放用 `screenToFlowPosition()` 换算回画布坐标，实时写 store（与节点拖动一致），不建 React Flow 节点。
- 标签始终实时跟随章节标题，不提供自定义名称（按用户反馈移除，避免区域名与章名不一致造成困扰）；旧数据中的自定义 `label` 在载入时丢弃。删除在选中标签条上操作，删除区域不删除章节。
- 显隐为界面级 `uiStore.regionsVisible`，不持久化；当前章节区域实线高亮，其余虚线弱化。
- 生命周期：换卷且章节所属画布改变时，UI 确认后删除旧区域（store 兜底）；删章、删卷级联清理；载入/存档时按章节当前所属画布过滤孤儿与错板区域。区域允许负坐标，尺寸下限 120×80。
- 几何仅用于取人与场景归属；快照冻结自己的 `regions` 副本，区域后期移动/缩放不改变已记录的历史场景。

### 5.3 章节快照

```ts
type CastRole = 'present' | 'mentioned';

interface ChapterSnapshotEntry {
  characterId: string;        // node.id；跨卷复制保留，作为身份
  stateId: string;            // 引用的状态（切章时还原为当前状态）
  role: CastRole;             // 在场 / 仅提及（区域中心点/边缘带自动建议）
  x: number;                  // 采集时绝对坐标，供切章回放
  y: number;
  parentEnvId?: string;       // 所在环境（回放时还原父环境）
  nameAtCapture: string;      // 人物被删后仍能显示；不用于覆盖当前名字
  stateLabelAtCapture: string;
  stateFingerprintAtCapture: string;
  origin: 'region' | 'manual';// 现版本均为 region；manual 仅兼容旧档
}

interface ChapterSnapshot {
  version: 1;
  boardId: string;            // 快照所属画布
  capturedAt: number;
  updatedAt: number;
  source: 'manual' | 'auto-outline' | 'auto-content';
  regions: ChapterRegion[];   // 冻结当时的区域几何
  entries: ChapterSnapshotEntry[];
  envRefs?: Array<{           // 可选：最小环境上下文，防止旧章读到后期改过的建筑描述
    id: string;
    name: string;
    etype: EnvironmentType;
    path: string;
    desc?: string;
  }>;
}
```

- 快照很小：只存引用、位置、父环境与少量元数据，不复制完整人物属性，不保存状态内容历史。
- 放入 `SimChapter.snapshot?: ChapterSnapshot`，随章节持久化和存档。
- **自动写入**：人物移动/拖入拖出区域/切换状态/改父环境/编辑环境/调整区域后，300ms 防抖合并写入当前章快照；内容无变化时跳过。切章、生成前、手动保存时都会先同步当前章场景。
- **切章回放**：按目标快照绝对坐标减去当前父环境绝对坐标得到相对位置；只移动快照内人物，快照外人物保持原位；父环境缺失回退根层；状态缺失保留当前状态。
- 解析规则：`snapshot.boardId` → `characterId` → `stateId`；找不到时按 `characterId` 跨画布回退（多卷阶段），仍找不到则显示 `nameAtCapture + stateLabelAtCapture` 并标注“资料缺失”，不得编造。

### 5.4 章节上下文

```ts
interface ChapterContext {
  activeChapterId: string | null;
}
```

- `activeChapterId` 已落地在 `uiStore`（不持久化，R1），大纲面板、正文面板、顶栏与画布区域共享。
- **不引入 `canvasMode`**（2026-10-24 用户拍板）：画布始终是可编辑的工作画布，不做节点变暗、冻结场景或只读视图；唯一视觉处理是现有「当前章区域高亮」。
- 切章时大纲/正文/名单面板读取同一份章节快照；画布先写回当前章场景，再还原目标章快照内人物的位置、父环境与当前状态。快照外人物保持原位。
- 所有切章入口（大纲/正文/顶栏/画布区域）统一走 `activateChapter`，避免不同入口行为不一致。

## 6. 作者工作流（目标形态）

### 6.1 建立本章

1. 在工作画布上把人物放进建筑/房间，设置每个人的当前状态；
2. 画本章区域，标签自动显示章节标题；
3. 区域内人物自动成为本章名单：中心靠内=在场，边缘带=仅提及；
4. 场景随画布自动记录，无需手动采集/刷新；
5. 需要调整名单时，直接移动人物进出区域或切换状态。

### 6.2 写本章

- 切换到大纲或正文章节面板：系统先写回上一章场景，再还原本章人物位置/父环境/状态；
- 生成时只读取名单内人物及其状态；
- 引擎提示词硬性规定：名单外不得新增具名人物；仅提及人物不得直接行动；
- 需要新人物时，回到工作画布把人物移入本章区域并设置状态，场景会自动更新。

### 6.3 看历史

- 切换章节 → 名单面板显示该章快照的在场/仅提及、状态与来源画布；
- 显示与上一章的角色/状态差异；
- 画布会还原该章场景（位置/父环境/状态），但属性内容始终取当前值，不保留历史版本；
- 环境布局视为固定，不随切章变化。

### 6.4 下一章

- 切到下一章：当前场景自动写回上一章快照；
- 在新章画布上移动人物、改状态、画区域；
- 新章场景自动记录，无需手动采集。

## 7. 关键规则

### 7.1 名单锁（必须实现）

- 快照 `entries` 是本章唯一合法出场名单。
- 生成提示词必须把「在场」与「仅提及」分开，并规定：
  - 不在名单内的具名人物不得出现；
  - 仅提及人物不得直接行动、说话或做出只有在场才能做的行为；
  - 不能自行补设定。
- 无名群演是否允许需要确认；建议允许**无名背景路人**，但禁止新增具名人物。若选择绝对严格，则完全禁止名单外人物。

### 7.2 状态锁（待确认）

“锁定”有两种强度：

| 方案 | 行为 | 存储/复杂度 | 建议 |
|---|---|---|---|
| A. 状态可变 | 改状态会改写引用它的历史章节 | 最低 | **已采用（配合影响提示）** |
| B. 被引用后只读 | 编辑时提示；要改用“复制为新状态” | 低 | 保留为可选安全路径 |
| C. 状态 revision | 每次编辑产生版本，快照记版本号 | 高 | 不做 |

**已确认（2026-10-24 用户决定）：采用 A + 提示**。不强制锁定、不做状态 revision：

- 状态被任一快照引用后，属性面板显示「被 N 章引用」，删除/修改前列出影响章节；
- 允许原地修改；改完重新生成历史章节即使用新内容（快照只存 `stateId`）；
- 保留「复制状态」作为安全的另存路径，不强制；
- 名字/性别在顶层，修改会影响所有章节 → 视为身份修正并提示；
- 人物形象属于状态；替换形象/头像同样影响被引用章节。

### 7.3 区域采集规则

- 采集对象只有人物节点，环境不进入 `entries`。
- 判定：人物节点**中心点**在矩形内即命中。
- 角色默认建议：
  - 人物父级环境在区域内（建筑/房间内）→ 建议 `present`；
  - 人物在区域边缘、无环境归属 → 建议 `mentioned`；
  - 最终以名单里的显式 `role` 为准，几何只是建议。
- **不再提供人工增删/角色切换/状态选择**（2026-10-25 用户确认）：名单完全由区域自动派生，调整方式就是移动人物进出区域。
- 快照保存时记住区域几何副本；之后移动区域不改变旧快照，而是触发当前章场景重新记录。

### 7.4 自动记录规则（已实现）

- 当前章区域内的场景（人物位置/父环境/状态）随画布自动写入本章快照，300ms 防抖合并；
- 触发条件：拖动人物、拖入/拖出区域、切换状态、修改父环境、编辑环境、调整区域；
- 内容无变化时跳过写入，保留原 `capturedAt`；
- 首次进入没有快照的章节：不移动人物，直接把当前画布记录为底稿；
- 生成大纲/正文前、切章前、手动保存前都会先同步当前章场景；
- 自动同步只改内存 Zustand 状态；只有顶栏「保存」/Ctrl+S 写 localStorage 并保存命名存档；
- 活跃章节只在保存成功后持久化，刷新后高亮同一章。

不保留快照历史版本的原因（用户决定）：

> 章节场景只存位置/父环境/状态 ID；人物状态内容改了，重新生成历史章节就使用新内容。需要保留旧描写时应另建状态。

### 7.5 切章还原

- 切换大纲/正文/顶栏/画布区域 → 统一走 `activateChapter`；
- 先写回当前章场景，再切到目标章所属画布，最后回放目标快照；
- 回放内容：快照内人物的绝对位置、父环境、当前状态 ID；
- 只移动快照内人物，快照外人物保持原位；
- 父环境已被删除 → 回退根层；状态已被删除 → 保留当前状态；
- 环境几何不参与还原，按当前环境布局计算相对位置；
- 目标章无快照 → 不移动人物，把当前画布记录为本章底稿；
- 生成时永远优先读本章快照，而不是当前工作画布。

### 7.6 编辑 Agent 同步（横切硬要求）

数据结构变动不能只改 store/UI，否则编辑 Agent 会继续按旧世界模型回答和落块。

设计初期记录的差距已随 V1 / S1–S3 / E1 消除。当前实现：

- `editorChatSystem()` 注入画布索引、卷列表、当前画布与章节列表；按名检索命中人物时给出当前状态、状态列表，只展开当前状态属性（用户点名状态标签时再展开该状态摘要）。
- `editorExecProtocol()` 人物块支持 `卷：`；已新增 `【人物状态】` 协议。旧人物块新建写状态0，更新写当前状态。
- `parseSimBlocks()` 识别 `【人物状态】`；状态块解析动作/状态/基于/新状态名与四类属性，控制行不污染多行字段，缺动作或无可写属性时带 `parseError`。
- `EditorRoomPanel` 状态块先于人物/环境分支处理；按规范化名字唯一匹配人物，支持新建/更新/切换/重命名/删除；人物/状态不存在、标签重复、默认状态删除、卷不存在时按钮禁用且不落地；状态块不会创建人物，也不会改名字/性别/所在/形象/头像。

每个切片按以下四条验收：

1. **看得见**：索引或按需检索能读到新维度（卷、状态、快照），不是把全量数据塞进提示词。
2. **表达得出**：执行协议能表达新动作，且字段缺省语义明确、向后兼容。
3. **落得安全**：解析、匹配、确认、引用保护完整；同名/跨卷/被引用状态不得静默写错。
4. **测得到**：解析器、落地、上下文各有测试；最终用真实模型在测试服走一遍「对话 → 块 → 落地 → 刷新/存档」。

如果切片不涉及编辑室，也必须保证旧协议不回归；涉及新维度的切片，不能把编辑能力留到以后。

#### 7.6.1 编辑能力归属

| 编号 | 编辑 Agent 能力 | 必须随哪个切片完成 | 要点 |
|---|---|---|---|
| E1 | 状态上下文 + `【人物状态】` 协议 + 状态落地 | **S2**（S1 先保证旧块兼容） | **已实现（2026-10-24）**：创建人物带状态0；新建/更新/切换/重命名/删除；默认状态禁止删除 |
| E2 | 被引用状态的保护与提示 | **R5** | 修改/删除被快照引用的状态必须提示影响章节；推荐「复制为新状态」 |
| E3 | 本章快照只读上下文 | **R6** | 知道在场/仅提及与引用状态；不把提及说成在场；不得声称已直接改快照（场景随画布自动同步） |
| E4 | 多卷上下文与目标卷 | **V1** | 知道卷列表、当前卷；跨卷操作必须写清 `卷：`，缺省只作用于当前卷 |
| E5 | 跨卷同名消歧与确认 | **V2/V3** | 同名人物必须按卷定位；跨卷复制/剪切第一版仍由 UI 执行，编辑 Agent 不自动改画布 |

补充：

- **S1**：旧 `【人物设定】`（没有状态字段）必须继续可用；更新落在当前状态，创建落在默认状态。
- **S3/S4**：编辑 Agent 不编造图片 key（`charimg:`/`charhead:`）或旧素材 ID；人物形象与头像由属性面板上传、AI 生成和裁切处理。状态块只改文本属性。Agent 可以**读取**形象图（2026-10-27）：仅在用户明确要求读取形象图/立绘/参考图（含「根据其形象重新设置」）时，编辑室才检索画布、把对应状态的形象大图以视觉输入附上，并在提示中标注人物与状态；普通提到人物不自动读图。群组请求（这些人/他们/全员）会展开环境成员或回看最近名单，超过 3 人时按每批 ≤3 张分多次请求并合并回复；图片只读不写回。
- **R3/R4**：人物/状态/环境落地后，当前章场景随画布自动同步（自动同步只改内存，需手动保存落盘）；编辑 Agent 不得声称已直接修改快照/名单/区域。
- **R1/R2**：区域和名单是画布/章节 UI 对象，编辑 Agent 不把它们当人物或环境节点；第一版不提供对话式改区域/改名单。

#### 7.6.2 上下文注入

现状是 `editorChatSystem()` 只注入 `simCanvasIndex()`、`canvasLookupBlock()`、章节列表和读写块；没有卷、状态、快照维度。目标形态：

**始终注入的轻量索引**（版本门控，未实现的维度不出现）：

```text
【画布索引】
当前卷：第二卷（当前编辑）
可用卷：第一卷、第二卷、第三卷
当前章：第二章《夜雨客栈》；快照：已记录（在场 3 / 仅提及 2）
人物：张三（男，当前状态：状态02）、李四（女，当前状态：默认）……
环境：客栈、码头……
```

- 人物只显示**当前状态标签**，不展开全部状态属性；
- 快照只显示数量与当前章，不展开名单；
- 无卷/无快照时保持现有索引格式，避免无意义占位。

**按需检索**（用户点名人物、状态或卷时）：

```text
【画布检索】张三
所在卷：第二卷
顶层身份：张三 / 男
当前状态：状态02（45岁）
状态列表：默认、状态01、状态02、重伤后
属性（状态02）：基础信息……；身份信息……；关系信息……
```

- 默认只展开**当前状态**的完整属性；
- 用户明确问“有哪些状态/状态02是什么/状态变化”时，再展开指定状态或状态列表摘要；
- 状态标签只在**已定位到人物之后**匹配，不能全局按“状态02”搜人；
- 同名人物分布在多卷时，检索结果必须标注卷；跨卷写入必须带 `卷：`，否则拒绝落地；
- 批量更新仍要求使用检索给出的**精确人物名**，一人一块，不能猜名字。

**本章快照上下文**（R6；只在章节模式或用户问本章时注入）：

```text
【本章快照】第二章（卷：第二卷）
区域：第二章（已冻结）
在场：张三[状态02]（客栈/二楼）、李四[默认]（客栈/大堂）
仅提及：王五[状态01]（区域边缘）
```

- 只有名字、角色、状态标签、父环境路径；属性仍需按需检索；
- 编辑 Agent 必须区分「在场」与「仅提及」：仅提及人物不得被描述为在场行动；
- 快照是只读上下文，编辑 Agent 不得声称已修改名单/区域，也不得自行把名单外人物写成本章在场；
- 用户要求“改本章的张三”时，编辑 Agent 应说明这会改工作画布，本章场景会随画布自动同步，不能声称已直接写快照。

#### 7.6.3 落地顺序与引用保护

- 同一回复中先 `【人物设定】` 后 `【人物状态】`；状态块依赖人物已经存在，落地按回复顺序执行；前一块失败则跳过依赖它的状态块并提示。
- 状态块不得隐式创建人物；人物名匹配不到时只报错，不新建。
- 修改/删除被快照引用的状态：
  - 落地前显示「该状态被 N 章引用」；
  - 推荐动作：取消 / 复制为新状态并替换本章引用 / 显式全局修改；
  - 删除被引用状态、删除仍被引用的人物：默认阻止；
- 重命名状态只改 `label`，`stateId` 不变；历史快照仍保留采集时的标签文本，UI 可同时显示当前标签。
- 顶层名字/性别修改影响所有章节，属于身份修正：允许但必须提示。
- 编辑 Agent 不自动跨卷复制/剪切、不直接改快照/名单/区域；场景由系统随工作画布自动同步。

#### 7.6.4 编辑同步的测试门槛

每个涉及编辑能力的切片，至少包含：

1. **解析器**：旧人物块无状态字段、旧批量更新、中文冒号/空格、缺字段、未知动作；
2. **落地**：默认状态创建、复制新建、指定状态更新、切换、重命名、删除保护、跨卷同名拒绝；
3. **上下文**：索引含当前卷/当前状态；按需检索能列出状态但不全量倾倒；本章快照在场/提及分组正确；
4. **真实模型 E2E**：在测试服公开入口让编辑 Agent 处理一条跨卷/状态指令，检查回复块、落地结果、刷新后持久化；
5. **回归**：旧对话块、批量更新、无状态人物、无快照章节。

### 7.7 编辑执行协议扩展

保持现有 `【人物设定】/【环境设定】/【区域规划】/【卷设定】/【写入】/【生图】` 块不变，新增 **`【人物状态】`** 块，并给人物块增加可选 `卷：`。

#### 7.7.1 `【人物设定】` 的兼容扩展

```text
【人物设定】
名字：张三
卷：第二卷
性别：男
年龄：30
基础信息：……
身份信息：……
所在：客栈/二楼
```

- `卷：` 可选；省略 = 当前工作卷；跨卷创建/更新必须写，且值必须与上下文卷名完全一致。
- 旧格式（无 `卷`、无状态概念）行为不变。
- 创建人物自动生成默认状态；块内属性写入默认状态。
- 更新人物且未指定状态时，属性写入**当前状态**（与用户在画布上看到的一致），不是永远写默认状态。
- 顶层 `名字/性别` 仍只由人物块修改；状态块不得修改。
- 现有 `更新：` 改名、`所在：` 仅在明确移动时输出等规则保留。

#### 7.7.2 `【人物状态】` 块

```text
【人物状态】
人物：张三
卷：第二卷
动作：新建
状态：重伤后
基于：状态0
年龄：31
基础信息：右臂骨折，失血过多。
身份信息：客栈护卫。
关系信息：对李四有救命之恩。
```

已实现的类型（`src/engines/studioEngine.ts`）：

```ts
type EditorStateAction = 'create' | 'update' | 'switch' | 'rename' | 'delete' | 'invalid';

interface EditorStateBlock {
  kind: 'characterState';
  label: '人物状态';
  character: string;        // 精确人物名
  volume?: string;          // 跨卷必填；缺省=当前卷
  action: EditorStateAction;
  state?: string;           // 新建=新状态标签；其余=目标状态标签
  baseState?: string;       // 新建时的复制来源；缺省=当前状态
  newLabel?: string;        // rename 的新标签
  age?: number;
  basicInfo?: string;
  identityInfo?: string;
  relations?: string;
  parseError?: string;      // 缺动作/修改未写属性等，UI 禁用并显示原因
}
```

`EditorRoomBlock` 与 `SimBlock` 已扩展出 `'characterState'`，落地逻辑与人物块共用画布/人物定位函数。

动作：

| 动作（同义词） | 必填 | 语义 |
|---|---|---|
| 新建 / 新增 | 人物、状态 | 复制 `基于` 状态的全部字段，再覆盖本块写出的字段；`基于` 省略时用当前状态；未写字段保留 |
| 更新 / 修改 | 人物、状态 | 只覆盖本块写出的字段；未写字段保留 |
| 切换 / 设为当前 | 人物、状态 | 把该状态设为当前状态（`activeStateId`） |
| 重命名 / 改名 | 人物、状态、新状态名 | 只改标签；`stateId` 不变；新标签在该人物内必须唯一 |
| 删除 | 人物、状态 | 默认状态不可删；被快照引用时仍允许，但必须列出影响章节（R5） |

字段规则：

- `状态` 是当前标签，必须在该人物状态列表中精确匹配；新建时作为**新标签**。
- 状态标签在一个人物内唯一；重复时拒绝，不能静默覆盖。
- 状态块只接受 `年龄/基础信息/身份信息/关系信息`；`名字/性别`、`所在` 不属于状态，解析器应提示改用人物块或 UI。
- `形象/头像` 不由文本块写入，避免模型编造图片 key；由属性面板上传/AI 生成/裁切处理。状态块新建时会完整复制来源状态的 `image` 引用（这是本地继承，不是模型输出）。
- `关系信息` 默认仍不在人物块输出；只有用户明确要求改关系、且使用状态块时才输出，控制提示词体积。
- 状态动作也必须一人一块；批量给多人建状态 = 多个块，不能把多人写进同一个 `状态` 字段。
- 创建人物并预设多个状态：先输出一个 `【人物设定】`，再按顺序输出多个 `【人物状态】`（动作=新建）；落地按回复顺序执行，人物块失败则依赖它的状态块跳过并提示。
- `卷：` 自 V1（2026-10-24）起正式生效：省略=当前画布，指定卷必须唯一匹配，找不到/重名拒绝落地且不回退当前画布。

#### 7.7.3 缺省语义（必须写进系统提示）

| 场景 | 缺省行为 |
|---|---|
| 创建人物，未写卷 | 当前工作卷，生成默认状态 |
| 更新人物，未写卷 | 当前工作卷 |
| 更新人物，未写状态 | 当前状态 |
| 跨卷人物操作，未写卷 | **拒绝并提示补卷**；若该名字只在另一卷唯一存在，也不静默跨卷写 |
| 新建状态，未写基于 | 复制当前状态 |
| 新建状态，未写属性 | 完整复制来源状态 |
| 状态块人物不存在 | 报错，不隐式创建 |
| 同名人物出现在多卷 | 必须带卷；否则拒绝 |

系统提示必须明确告诉编辑 Agent：它只能使用索引/检索给出的精确卷名、人物名、状态标签；不能编造状态名，也不能在回复里声称“已修改”而实际没有块。

### S4 人物形象大图 + 手动裁切头像（已实现，2026-10-26）

**产品决定**

- 每个状态保存一张**自己的**人物形象大图，支持常用预设尺寸与原图尺寸；
- 画布头像不再使用素材库小图，而是用户从大图中手动框选头部区域生成的圆形头像；
- 没有形象或没有裁切头像时，按性别显示内置男女剪影；
- 旧“写真”UI 取消，旧 `avatar` / `portraitKey` 不迁移。

**数据与存储**

- `CharacterState.image: CharacterStateImage`，见 §5.1；
- 大图 key `charimg:<nodeId>:<stateId>:<nonce>`，头像 key `charhead:<nodeId>:<stateId>:<nonce>`；
- nonce 保证换图/重裁 copy-on-write：继承同一张图的其它状态不会被原地覆盖；
- 图片本体只进 IndexedDB（`nc2-imglocal-v1`/`imgs`），状态/存档只保存元数据。

**图片处理**

- 上传：接受 PNG / JPEG / WebP，≤20MB，保留原图尺寸；最长边 >4096 时等比缩小；统一输出白底 JPEG（质量 0.9）；
- AI：按预设构图生成，客户端请求比例 + `2K` 档位，再 cover 裁切/缩放到精确像素：
  - `1:1` 1024×1024、`4:3` 1440×1080、`16:9` 1920×1080、`9:16` 1080×1920；
- 头像：源图像素方形 crop → 256×256 JPEG；裁切弹窗提供拖动整框、四角等比缩放、圆形实时预览；
- 所有写库失败（配额等）都提示错误且不更新状态元数据。

**清理与复制**

- `releaseCharacterImageKeys` 扫描全部画布的节点/状态，只删除已无任何引用的 key；
- 更新状态、删除状态、删除节点后都走同一引用检查；
- 跨卷“复制为新”逐状态重写 `image.key/headKey` 并复制图片；镜像共享 key、不复制字节；
- 旧 IDB 孤儿字节不自动删除。

**Agent 读取形象（2026-10-27，仅明确要求时；支持群组批量）**

- 只有消息中出现明确读图要求（`形象图 / 形象大图 / 人物形象图 / 立绘 / 画像 / 参考图 / 原图`，或「读取/看看/参考/对照…形象」；或「根据/按照其/这些人的形象重新设置/统一/调整」）才检索当前画布；普通提到人物、讨论长相不搜索、不附图；
- 群组目标解析优先级：
  1. 本轮点名的全部人物（按出现顺序，不再只取相似度前 6）；
  2. 本轮点名环境 + 「里面/所有人」→ 该环境及下层成员；
  3. 「这些人/他们/其」没点名 → 回看最近 16 条消息（用户与 agent 都算）里最近一次人物名单或环境成员；
  4. 群组说法仍无目标 → 当前章快照名单（快照属于当前画布时）；没有快照 → 当前画布所有有名字的人物；
- 状态优先当前消息点到的状态名，其次章节快照状态/沿用消息里的状态名，再退到当前状态与第一个有图状态；提示中始终标注实际人物/状态；
- 群组上限 12 人；按每批 ≤3 张、最多 4 批**顺序请求**，每批系统提示「第 i/n 批，只分析和处理本批附图人物」，避免模型对没附图的人编造形象；
- 多批结果合并成一条 agent 回复（`【第 i/n 批：人物…】`标题 + 各批正文）；blocks/writes 合并到同一条供一键落地；编辑记忆按 target 合并；气泡列出全部已读人物并标注「分 n 批分析」；
- 明确读图时不再携带历史附图，避免旧图占满 4 张预算；当前消息附图仍保留，每批大小为 `min(3, 4-当前附图数)`；
- `loadCharacterVisionImage` 从 IndexedDB 读**形象大图**，最长边 >1024 时缩放重编码；大图缺失直接跳过（不回退头像）；
- 仅私有视觉模型启用，公共模型静默跳过；未明确要求写入时不自行改设定；图片只读不写回。

**边界**

- 命名存档 / JSON 导出仍只含元数据，跨浏览器导入后显示“图片缺失”并回落剪影；
- 头像异步读取，冷启动会先剪影后切换；模块级缓存减少闪烁；
- 编辑 Agent 只能在文本属性上操作，不输出 `charimg`/`charhead`；读图不改变形象本身。

**验收（部署环境 Playwright，`g:\tmp\e2e_character_image.py`）**

- 旧 avatar/写真字段被丢弃，男女剪影正确；
- 上传 800×600 保留原尺寸，刷新后大图仍在；
- 裁切框可拖动/缩放，保存 256×256 头像，画布为圆形头像；
- 新状态继承图片引用；换图后 key 不同、原状态不受影响；
- 共享 key 移除一个引用仍保留，最后一个引用删除后清 IDB；
- AI 16:9 请求 `size=16:9`/`imageSize=2K`，落库精确 1920×1080，并自动打开裁切；
- Ctrl+S 刷新后大图/头像保持；>20MB、SVG、GIF 被拒绝且不覆盖现有形象；
- 移动端 390×844 裁切弹窗不溢出、可操作。

**Agent 读图验收（部署环境 Playwright，`g:\tmp\e2e_editor_char_image.py`）**

- 普通提人不检索画布；明确要求读取才附图；
- 点名状态附该状态大图；代词请求回看最近点名与状态；无形象/公共模型不报错；
- 群组点名 3 人 → 单次请求附 3 张，逐人标注，不分批；
- 「根据这些人的形象统一重新设置」→ 从环境成员解析出 5 个有图人物，按 3+2 两次请求；两批提示分别标注「第 1/2 批」「第 2/2 批」，回复合并为一条气泡并列出全部人物。

### P1 持久化（手动保存）

> **实现状态（2026-10-24，已部署验收）**：最初采用自定义 `PersistStorage` 500ms 防抖落盘；同日按用户反馈改为手动保存，未做按 board 分片/IndexedDB。当前实现见 `src/stores/manualPersistStorage.ts`。

**当前行为**

- Zustand `PersistStorage.setItem` 只登记最新内存 payload，不写 localStorage；`save()` 在用户点顶栏「保存」或 Ctrl/Cmd+S 时写入 `nc2-sim-v1`，并同步同名命名存档。

- 有未保存改动时工具栏显示「有未保存改动」，刷新/关闭页面由浏览器弹出离开确认（不自动保存）。
- 载入命名存档、新建作品属于显式操作，会立即写入当前作品；打开/新建/导出前如有未保存改动会提示。
- 写入失败保留待保存内存状态并显示错误，直到下一次保存成功；超配额有明确提示。

**验收**

- 编辑/流式生成期间 localStorage 不产生自动写入；
- 选中、平移、缩放不误报未保存；
- 按钮与 Ctrl+S 落盘，刷新后恢复上次保存版本；

## 11. 风险与应对

| 风险 | 影响 | 应对 |
|---|---|---|
| 状态可变导致历史被改写 | 旧章人物设定变化 | 已拍板不锁定：修改/删除前列出影响章节；重新生成使用当前内容，不保留历史版本 |
| 自动场景写回覆盖旧章 | 在错误章节移动人物会改写该章场景 | 场景只写当前活跃章节；切章前先写回、切章后回放；首次无快照不移动人物 |
| 区域几何误判在场/提及 | 名单错误，生成跑偏 | 几何只做建议；调整方式是移动人物进出区域 |
| 引用的人物/状态被删 | 章节快照解析失败 | 删除前列出影响章节；缺失时降级显示「资料缺失」，不猜补 |
| 环境未随快照冻结 | 旧章读到后期改过的建筑描述 | 快照附带最小环境上下文（envRefs） |
| 图片 key 冲突 | 状态间形象/头像互相覆盖 | key 带 node+state+nonce；换图 copy-on-write；清理前跨全部画布做引用检查 |
| 多卷/快照数据膨胀 | localStorage 超限、卡顿 | 现为手动保存，不再频繁全量序列化；超配额有提示，数据继续增大时再评估分片/IndexedDB |
| 名单锁只靠提示词 | 模型仍可能编造人物 | 强化提示词；结构化的名单块；人工审核；不做无把握的自动文本校验 |
| 一章多场景 | 单区域/单名单无法表达分场景 | 第一版一章一区域；数据模型预留多区域；后续 scenes |
| 章节跨卷移动 | 区域和快照 board 不一致 | 换卷时删除旧区域并提示；快照保留原 board，V3 唯一回退或标记缺失 |
| 编辑 Agent 编造状态名/卷名 | 状态块落到错误目标或反复报错 | 只使用索引/检索给出的精确值；解析后按卷+人物+状态精确匹配；匹配失败不写入 |
| 跨卷同名人物被静默写错 | 改错卷的副本，作者难发现 | 同名/跨卷必须显式 `卷：`；未写卷拒绝；落地前显示目标卷 |
| 编辑 Agent 声称已改但无块/落地失败 | 用户误以为快照已同步 | 成功状态只由 UI 落地结果决定；系统提示禁止空口声称；失败逐块提示 |
| 编辑改工作画布后快照过期 | 章节生成与画布认知不一致 | 场景随画布自动同步；生成/切章/保存前强制同步 |
| 编辑 Agent 自动跨卷/改快照 | 破坏性副作用 | Agent 只改工作画布；场景由系统自动同步；跨卷复制/剪切仍由 UI 确认 |
