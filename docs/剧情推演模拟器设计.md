# 剧情推演模拟器设计 · 设计稿（待开发）

> 状态：**设计稿**（2026-10-29 起草，同日两次修订，未经实现）。本文回答「是什么、为什么这样设计、落在哪里」，实现前需过一遍 §17 待确认决策。
> 定位：与现有「自上而下」创作流程（目标 → 规则 → 卷 → 大纲 → 正文）并列的第二种模式——**自下而上**：人物在**独立舞台画布**上按世界模型自主行动，剧情从模拟中涌现，作者观察、挑选、记录成剧情脚本，再交给正文生成。
> 前置阅读：[人物编辑库设计](人物编辑库设计.md)、[章节画布与人物状态设计](章节画布与人物状态设计.md)。

## 1. 需求

用户原始诉求（三轮）：

> ① 整个小说作品的构建过程基本是自上而下的搭建，我现在需要另外一种模式，可以从下而上地搭建。这是一个剧情推演模拟器：所有在场人物会进入实时模拟状态，可以指定人物记录其行为过程和事件链，作为剧情脚本，用于生成正文。在当前的系统之上，首先对人物有额外的要求，例如有扩展属性，有根据作品需求定义的不同欲望，在不同属性和欲望下产生的行为。同时需要一个系统层面的 skill，用于构建这些属性和行为的定义，使其数值架构合理、运行时能涌现内容。
>
> ② 这个模块需要一个**独立的画布**，与卷画布并列，可以称为**舞台**或**演播室**。其次，需要一个**基础世界模型**，能支持人物执行基础逻辑，例如移动、观察、感知。所有作品需求都在更高一层，统一视为**欲望层**——不同的作品为不同的人物添加特殊的欲望，例如探索欲、生存欲、爱情欲等等。
>
> ③ 当前的环境系统**没有路径和门的概念**，这在推演环境中是个大问题，需要补充。人物的**移动、行为都需要耗时**，以产生多人、多个行为的时序性。

分解为八条可实现的诉求：

1. **独立舞台画布**：与默认主画布、各卷画布并列的一张专属画布，模拟只在这里发生。
2. **基础世界模型**：系统内置的空间 / 拓扑 / 感知 / 移动 / 观察 / 交互原语，不由作者编辑。
3. **路径与门**：环境之间需要显式的连通拓扑——通道决定「能不能过去、绕多远」，门可以锁。
4. **耗时与时序**：移动按距离耗时、行为按拍数耗时；多人动作在时间轴上重叠、排队、争抢，事件带时间跨度。
5. **欲望层**：作品的一切叙事需求统一翻译成欲望（探索欲 / 生存欲 / 爱情欲 / 复仇欲…），作品级定义、可逐人物指派调参。
6. **行为层**：作品级定义行为（欲望的满足手段），建立在世界模型原语之上。
7. **实时模拟**：舞台人物按节拍自主决策，可暂停、单步、干预；可指定人物记录行为过程与事件链。
8. **剧情脚本 → 正文**：事件链沉淀为剧情脚本供正文生成消费；系统级技能「数值架构师」辅助构建定义并保证数值架构合理。

## 2. 现状：地基与缺口（2026-10-29 调查结论）

| 草稿-确认落地制 | `parseSimOutput` → `SimWriteButtons` / `SimBlockDropRow.drop` | 架构师产出与脚本写入的安全通道 |

### 2.2 缺口

1. **无独立舞台**：现有板全部派生自卷或主画布；舞台不加标记会落进 orphan 分支。
2. **环境无拓扑**：只有几何与嵌套，没有「哪两个环境之间能走、怎么走、门是否锁」的概念——直线移动等于穿墙。
3. **无时间模型**：全仓库无 tick/节拍；动作瞬时完成，多个动作在同一点发生，无法产生多人行为的重叠与先后。
4. **无世界模型运行时**：没有感知范围、视野、观察揭示，人物也没有「见过谁、去过哪」的知识状态。
5. **无欲望/行为数值体系**：人物属性除 `age: number` 外全是文本段；`Math.random` 仅 3 处且全是 ID 生成，无 seeded RNG。
6. **无结构化事件日志与脚本产物**：大纲「本章事件链」是文本模板；输出通道只有设定块/写入块/正文。

## 3. 总体架构：舞台 + 分层世界 + 时间轴

```
┌─ 舞台画布（作品内固定一张，kind='stage'）───────────────┐
│ 环境布局 + 通道（门/路径）+ 人物放置 = 推演的物理世界      │
│ 可从卷画布一键镜像布局；推演结果不写回任何卷画布          │
└──────────────────────────────────────────────┘
        ↓ 参演（舞台上的放置 = 在场人物）
┌─ L0 世界模型（系统内置，不可编辑）──────────────────────┐
│ 空间：环境嵌套树 + 几何坐标                             │
│ 拓扑：通道图（门/路径/窗），可锁；显式拓扑 or 降级直连    │
│ 感知：同环境互见（距离过滤）+ 邻接环境名称模糊可见 + 进行中动作可见│
│ 移动：沿通道图寻路，逐 tick 步进，穿门/绕路都耗时         │
│ 观察：observe 原语，揭示环境/人物/物品 → 知识            │
│ 交互：同环境互见即可互相作用                             │
│ 新颖度信号：新环境/新面孔 → 供探索类欲望结算             │
└──────────────────────────────────────────────┘
        ↓ 原语之上；一切动作占用时间
┌─ L1 行为层（作品级定义）───────────────────────────┐
│ 行为 = 条件（属性/场地/同伴）+ 效果 + 移动意图 + 耗时     │
└──────────────────────────────────────────────┘
        ↓ 行为服务于
┌─ L2 欲望层（作品级定义 + 人物指派）───────────────────┐
│ 探索欲/生存欲/爱情欲/复仇欲… 每 tick 增长，被缓解/超阈值 │
└──────────────────────────────────────────────┘
        ↓ 时间轴推进（tick）
┌─ 事件链（带 startTick→endTick 的结构化 SimEvent）──────┐
│ 多人在同一时间窗内的动作重叠、排队、争抢 → 时序性        │
└──────────────────────────────────────────────┘
        ↓ 事件段批量（低频 LLM，单向不回写）
┌─ 叙事化文本 → PlotScript 剧情脚本库 ─章节槽位→ 【剧情脚本】块 → 正文生成
```

三条设计判断：

- **世界模型固定、欲望开放**（D13）：移动/观察/感知/门这类基础逻辑不让作者定义，系统内置成不可编辑的能力层；作品只定义「人物想要什么、为此做什么」。
- **数值决策 + LLM 叙事化**（D1）：数值层高频免费试错，叙事层低频生成文本，单向数据流。
- **时间是一等公民**（D18）：tick 是抽象节拍，动作有耗时与占用，事件带时间跨度——时序性是剧情感的来源，不是事后排的。

## 4. 舞台画布（独立演播室）

### 4.1 定位与生命周期

- 作品内**固定一张**舞台画布：`id='stage'`，`kind='stage'`。与默认主画布、卷画布在 tab 栏并列（「🎬 舞台」）。
- 不参与卷派生，**不可删除**，只能「清空舞台」（清节点与通道，保留空板）。
- **布局导入**：任意画布可「复制布局到舞台」——复用 `planBoardCopy` mirror 语义（同人物放置 + 同环境结构 + **同通道**，`edges` 已按 `source|target` 复制），一键把某卷搬来当推演底稿。反向不做。
- **不进章节体系**：舞台板不参与章节区域、章节快照自动同步、编辑 Agent 画布索引/检索。

### 4.2 数据模型改动

```ts
// types/sim.ts — SimBoard 增加可选标记（additive，旧存档天然兼容）
export interface SimBoard {
  id: string;
  /** 🎬 板类型：'stage' = 推演舞台；缺省 = 默认主画布/卷画布（既有语义不变） */
  kind?: 'stage';
  volumeId?: string;
  nodes: SimNodeType[];
  /** 除既有网格/连线外，'portal' 类型的边承载环境通道（见 §5.2）；其它边仍保持原样 */
  edges: Edge[];
  regions: ChapterRegion[];
  viewport?: SimViewport;
}
```

```ts
// boardOps.ts
export const STAGE_BOARD_ID = 'stage';
export const STAGE_BOARD_LABEL = '🎬 舞台';
export function stageBoard(): SimBoard { return { id: STAGE_BOARD_ID, kind: 'stage', nodes: [], edges: [], regions: [] }; }
```

五处配套（按依赖序）：

1. `sanitizeBoards`（studioStore.ts:475-478 卷补板同处）：始终保证 `boards[STAGE_BOARD_ID]` 存在且 `kind:'stage'`。
2. `boardLabel`（boardOps.ts:33）：舞台常量优先于 volumeId 分支。
3. `StudioPage.tsx:411-418`：`knownBoardIds` 加入 stage；tab 栏在默认主画布之后渲染舞台 tab。
4. `resolveBoardRef`（boardOps.ts:63）：**不认**舞台——编辑 Agent 不能向舞台投放（沙盒隔离，D15）。
5. `clearLiveWork`（Bookshelf）：舞台板由 sanitize 保证存在，清空作品后是空舞台。

「清空舞台」= 移除舞台全部节点（放置清除、人物库保留）+ 全部通道 + 清空 session。

### 4.3 参演与记录

- **参演人物** = 舞台人物放置全集；推演入口只在舞台 tab 常驻。
- 启动时冻结参演名单 + 当前状态 + 初始位置进 `SimPlaySession.actors`（存 `stateFingerprint` 供恢复时漂移检测）。
- 推演 running 时舞台只读（暂停后可编辑，提示「修改在下次重置后生效」）。
- **记录人物**：1 个主视角必选 + 可选旁观者（`recordedCharacterIds: string[]` 已留位，v2 多视角脚本）。

## 5. 世界模型 L0（系统内置，不可编辑）

新文件 `src/engines/simWorldModel.ts`，纯函数 + 常量：把画布几何与通道翻译成「谁看得见谁、能不能走、要走多久、观察能揭示什么」。

### 5.1 空间

- 消费环境嵌套树：容器类型构成包含关系（`parentId`），`item` 非容器。
- 人物运行时位置：`{ x, y, envId }`，`x/y` 为绝对坐标（overlay 直接画），`envId` 为最近包含它的容器（每 tick 依据几何重算，复用 `findContainerAt`）。
- 初始位置由放置节点坐标换算。

### 5.2 拓扑：门与路径（本次新增的核心）

**载体**：通道 = React Flow 边（`type:'portal'`），域属性存 `edge.data`。理由：`edges` 已被渲染/复制/剪除/存档，只是从未有创建入口；用户「两点连线」即建通道，最自然的画布交互。

```ts
export interface SimPortalData {
  kind: 'door' | 'path' | 'window' | 'gate';
  /** 名称：「后门」「密道」「窗台」 */
  name?: string;
  /** 锁闭：阻断通行（作者布置或导演干预切换）；钥匙/条件留 v2 */
  locked?: boolean;
  /** 通行额外耗时（tick），默认 door/path=0，gate=1 */
  traverseCost?: number;
  /** 单向（默认双向）；单向时 source→target 可走，反向不可 */
  oneWay?: boolean;
}
```

**拓扑模式（渐进式，D17）**：

| 模式 | 触发条件 | 规则 |
| --- | --- | --- |
| **显式拓扑** | 板上存在 ≥1 条 portal | 只有通道连接的两个环境相邻；跨环境移动必须沿通道图寻路。锁闭/单向通道断开。 |
| **降级直连** | 0 条 portal | 父↔子、同父兄弟之间视为全连通（无墙）；仅用于「先跑起来」，面板黄条提示「未布置通道，移动按无墙拓扑，门不生效」。 |

- **一键骨架**：「为每个子环境与其父环境生成门」——生成的是星形走廊拓扑（房→楼→房），正好符合现实；再按需补房间之间的直连门。
- **孤立环境诊断**：进入舞台时从当前人物位置做连通性检查，列出不可达环境；推演中人物目标不可达 → 行为不可行 + 「无路可走」事件（限频防刷屏）。这是作者补门的自检提示。
- **删除联动**：删环境节点时现有逻辑自动剪除其边（studioStore.ts:1619），通道天然清理；sanitize 丢弃端点非环境或端点已删的 portal 边。
- **通用性**：通道数据属于环境系统（任意画布都可画、可见、随存档），v1 只有推演消费它；卷画布上的通道不影响章节生成与快照。

### 5.3 感知

| 层 | 规则 | 得知内容 |
| --- | --- | --- |
| **直接感知** | 同 `envId` 且直线距离 ≤ `PERCEPT_RANGE`（默认 400px） | 对方姓名 + 可见状态标签 + **进行中的动作**（「看见两人正在争执」）；所在环境名/类型/描述 |
| **环境感知** | 同一父容器的兄弟环境，或父容器本身 | 环境名称与类型（「旁边有个房间」），不知内部有谁 |
| **记忆感知** | 知识里已记录的环境/人物 | 上次观察时的名单与描述，**可能已过时**（戏剧性错误的来源） |

- 感知被动、每 tick 自动更新；`knowledge.lastSeen` 记录最近看见某人的 tick。
- 进行中动作对直接感知可见——这是「A 在场时 B 推门进来撞见」这类时序叙事的机制基础。
- 环境级感知不受距离限制；跨容器不感知（窗 `kind:'window'` 的通道 v2 可允许跨容器互见）。

### 5.4 移动与寻路（耗时）

- **寻路**：在图（环境为节点、通道为边）上 BFS 求最短跳数路径；锁闭/单向通道按方向过滤。同环境内移动无需路径。
- **路点**：沿路径逐段行走——每段从当前点走到通道中点（近似：两端环境中心的连线中点），穿过后进入下一环境，最后走到目标环境中心。
- **耗时**：移动是连续过程，每 tick 推进 `SPEED`（默认 80px）+ 穿越门时额外 `traverseCost`。跨城镇（几百 px）自然比跨房间慢——**空间距离由此获得时间意义**。
- 移动中人物状态为 `moving`，不参与决策；到达后产生「到达 X」事件（低权重，可关）；穿门事件可选（默认关，避免刷屏）。
- **目标不可达**：路径不存在（锁门/孤立）→ 行为不可行，人物改选次优行为或原地兜底。
- 不做 A* 与障碍物绕行（画布是示意地图，通道图已表达通行性）。

### 5.5 观察（observe）

- 系统原语行为，不可删除（可调冷却权重）：花 `OBSERVE_DURATION`（默认 1 tick）观察当前或相邻环境 →
  - 揭示该环境：名称/类型/描述 + 内部人物名单 + 物品清单 + 进行中的动作；
  - 写入知识（`knownEnvIds` / `knownActorIds` / `observedAt`）；
  - 产生低权重事件「X 在 Y 张望」。
- 观察是**探索类欲望的主要满足通道**（§5.7），也是空定义时的保底动作。

### 5.6 交互

- 同环境、互见的人物之间才能发生 `requireCompanion` 行为；目标选择 = 互见者中「与本次行为相关欲望最强」者。
- **目标必须空闲**：对方正在 `acting` 或 `moving` 时不可作为互动目标（v1 不做打断），因此多人互动天然需要排队——时序性的又一来源。
- 行为正 `desireEffects` 同时作用于目标（「挑衅」加剧对方愤怒），形成冲突链。

### 5.7 新颖度信号

```ts
export interface SimKnowledge {
  knownEnvIds: string[];
  knownActorIds: string[];
  observedAt: Record<string, number>;   // envId → tick
}
```

每 tick 结算 novelty：新到达的环境 + 新观察到的人物/环境 → 对 `satisfiedBy:'novelty'` 的欲望按 `noveltyRelief`（默认 25/次）缓解。探索欲因此不必由作者硬写行为。

### 5.8 空 schema 兜底

无作品欲望/行为时，以 `idleWeight` 驱动原语：张望 → 沿通道走向未到过的环境 → 再张望。作品可「先跑起来再调参」，事件日志不断流。

### 5.9 常量

`PERCEPT_RANGE 400 / SPEED 80 / ARRIVE_EPS 12 / OBSERVE_DURATION 1 / NOVELTY_RELIEF 25 / IDLE_WEIGHT 1`——引擎常量，面板「世界模型」页只读展示，v1 不开放编辑（避免作者陷入调引擎）；开放为作品级可调项留 v2。

## 6. 欲望层 L2 与行为层 L1（作品级）

### 6.1 总原则

> **作品的一切叙事需求，都翻译成「某个人物在某种条件下产生某种欲望」。**

欲望是唯一驱动力；行为是满足手段；世界模型（空间/门/时间）提供满足所需的物理条件。

### 6.2 欲望分类法（架构师建议模板，不强制）

| 类别 | 典型欲望 | 建议增长 / 阈值 | 世界信号耦合 |
| --- | --- | --- | --- |
| 生理 | 生存欲、饥饿、休息欲、恐惧 | 0.6-1.0 / 60-80 | 属性门槛、环境安全度 |
| 社会 | 爱情欲、归属欲、权力欲、认同欲 | 0.8-1.2 / 50-70 | 同环境互见人物、关系文本 |
| 认知 | **探索欲**、求知欲 | 0.5-0.8 / 40-60，`satisfiedBy:'novelty'` | 新颖度、未到过的环境 |
| 情感 | 复仇欲、怜悯欲、执念 | 1.0-1.5 / 65-85 | 目标人物在场、记忆过时、门被锁 |

## 7. 时间与节拍引擎

新文件 `src/engines/simPlayEngine.ts`，**全部纯函数**，由 store 外的定时循环驱动 `step()`，按批写回。

### 7.1 时间模型

- **tick = 基本时拍**（叙事上约 1-2 分钟，UI 不展示真实时长，由叙事化层转译为场景时间）。
- **动作有耗时**：行为 `duration`（默认 1）；移动按距离/速度自然跨多拍；穿门按 `traverseCost` 额外计拍。
- **人物状态机**：`idle → moving → acting(until endTick) → idle`。忙碌者不感知决策（感知照常更新），不可被互动瞄准。
- **效果在完成时一次性结算**（避免逐拍累计歧义）。
- **同拍并发**：按 `characterId` 排序（seed 平局）确定性执行。互斥占用（`exclusiveTarget`）与「目标必须空闲」规则使第二人不可行 → 换次优行为 → 产生「受阻/犹豫」事件（争床、抢位、想搭话对方正忙）。
- **事件带时间跨度**：`SimEvent { startTick, endTick, status:'doing'|'done'|'blocked' }`；日志显示 `[t3→t7]`，进行中的动作实时可见并可被感知。
- **时序性的三个来源**：① 耗时导致动作重叠（A 正在争执时 B 才推门进来）；② 排队与互斥（同一张床、同一个对话对象）；③ 移动耗时（远端人物晚到，错过事件）。
- 推演速度 = 每拍真实毫秒（0.5s/1s/2s/5s 可调），与故事时间无关。

### 7.2 tick 流程

每拍对全体 actor（按 id 排序）依次执行：

1. **位置推进**：`moving` 者沿当前路点前进 `SPEED`；抵达路点/目标即切换；到达产生「到达」事件。
2. **动作完成结算**：`acting` 者若 `endTick == tick` → 应用 effects（欲望/属性 clamp）→ 写完成事件 → 状态回 `idle`。
3. **感知更新**：重算直接感知（含他人进行中动作）与环境感知；更新 `knowledge`。
4. **新颖度结算**：新环境/新面孔 → novelty（缓解 `satisfiedBy:'novelty'` 欲望）。
5. **欲望演化**：`intensity = clamp(intensity + growthPerTick, 0, max)`。
6. **冷却递减**。
7. **决策（仅 idle）**：§7.3 评分，选最高分行为；无可用行为 → 原语兜底（观察/走动）。
8. **开始动作**：算路径与耗时 → `action = {startTick: tick, endTick: tick + duration + moveTicks}` → 写开始事件；移动意图先置 `moving`。
9. **事件剪枝**：环形上限 500，最旧截断（已叙事化的在脚本里）。

### 7.3 效用评分

```
score(b) = Σ_d [ intensity(d) × max(0, −effect_b(d)) ]        // 欲望越强、缓解越多越有吸引力
         + Σ_n [ intensity(n) × noveltyRelief × noveltyHit_b ] // novelty 型欲望：观察/去未知环境有分
         × feasibility(b)                                     // 属性门槛 × 场地 × solo/companion × 目标空闲 × 路径可达
         × weight(b) × cooldownGate(b) × noise                // 冷却中=0；noise∈[0.9,1.1] seeded
```

- 属性只做门槛与消耗，不进效用（避免双系统打架）。
- 加剧型行为不直接产生效用，靠权重与传播制造剧情。
- **可复现**：`mulberry32(seed)`，按 `(tick, actorId)` 派生子种子；同 seed + 同 schema + 同初始态 = 逐拍一致的事件链（测试硬断言）。

### 7.4 涌现从哪来

| 机制 | 设计着力点 |
| --- | --- |
| 欲望冲突 → 摇摆 | 至少一对欲望在效果上互斥（满足 A 加剧 B） |
| 世界信号 → 自发行动 | 探索欲 × 未到过的环境；生存欲 × 低体力 → 回家 |
| 门与路径 → 戏剧门槛 | 锁门断路 → 绕远/被困/错过；远距离移动 → 迟到与错过 |
| 时间重叠 → 撞见 | 动作有耗时而感知可见进行中动作 → 「推门看见」 |
| 竞争 → 排队与受阻 | 互斥占用、目标忙碌 → 次优行为与受阻事件 |
| 条件行为 → 爆发点 | 门槛行为不可用时走保底，条件满足即爆发 |
| 阈值错拍 | 各欲望 threshold 错开 ≥20%，全场不同时进入主导 |
| 互动传播 | 加剧行为传染同环境目标，单人物冲动变多人冲突链 |
| 记忆过时 | 按旧印象行动（去了才知道人已不在） |
| 冷却节奏 | 冷却长短本身是节奏设计 |

### 7.5 运行模式

- **自动**：定时循环，0.5s/1s/2s/5s 可调，暂停/继续。
- **手动单步**：「下一步」调同一个 `step()`——逐拍观察。
- 两模式共用引擎（D9）。

## 8. LLM 叙事化层

`src/engines/simNarrator.ts`。**只读数值世界，不回写数值**（单向流）。

- **批量粒度**（D6）：取 8-12 个事件（或用户框选时间段）打包：事件序列（含 `startTick→endTick`、主导欲望、受阻信息）+ 人物卡（basicInfo/identityInfo/relations 截断 + 当前欲望）+ 环境路径 + 通道与锁门状态 → 单次调用产出叙事。
- 系统提示要求：按时间顺序覆盖全部事件（含并发的先后关系）、主导欲望转译为心理与节奏（不出现裸数值）、受阻与迟到写成场景冲突、环境用真实路径、不得新增或改变事件结果。
- 产出回填 `SimEvent.narrated` 与 `PlotScript.narrative`；失败可重试，重试不改变事件。
- **导演干预 v1**：暂停态下——① 调某人物某欲望强度；② 强制某人物下一拍执行指定行为；③ **开关某扇门**（上锁/开锁，D19）。均产生 `manual` 标记事件，叙事化一并覆盖。任意事件注入留 v2。

## 11. 系统级技能：数值架构师

### 11.1 定位

**不进用户写作技能库**（`nc2-writing-skills-v1` 无内置条目是刻意设计）。形态照 `memoryTemplates` 先例：系统内置规范 = 推演面板「AI 构建设计」按钮的 system 提示 + 专用产出协议块。

### 11.2 输入与产出协议

输入：全文目标/规则摘要、人物库摘要、舞台环境类型与**通道图统计**（门数/锁定门/孤立环境）、题材提示、可选「空跑 20 拍的事件日志」（诊断式建议）。

产出【推演设计】（逐行结构化 → 校验器 → 草稿确认制）：

```
【推演设计】
属性｜体力｜0-100｜默认 80｜耗尽只能休息
欲望｜探索欲｜认知｜0-100｜默认 40｜增长 0.7/拍｜阈值 55｜新颖度满足
欲望｜复仇｜情感｜0-100｜默认 20｜增长 1.2/拍｜阈值 65｜目睹仇敌后增长，公开清算后缓解
行为｜摊牌｜当众挑明恩怨｜复仇-35｜安全-15｜需同伴｜耗时 3｜冷却 8
行为｜寻访｜去没去过的地方看看｜探索欲-20｜移动 2｜耗时 2｜冷却 2
行为｜休息｜找个地方恢复体力｜体力+30｜需 房间/床｜耗时 6｜独占目标｜冷却 4
行为｜闲逛｜四处走动观察｜无门槛保底｜耗时 2｜冷却 2
指派｜李刚｜复仇 70、探索 20
```

### 11.3 设计准则（系统提示硬性要求）

1. 欲望 3-5 个，至少一对张力对。
2. 每个欲望至少 2 个满足行为（不同场地或条件）。
3. 至少 1 个阈值属性做可行性门槛。
4. 各欲望 `threshold` 错开 ≥20%。
5. 单行为对单欲望缓解量 20-40，不允许一拍清空。
6. 必须有 2-3 个无门槛保底行为。
7. 至少 2 个行为依赖他人在场，制造人物间耦合。
8. `growthPerTick` 按目标节奏反推：20-40 拍触发一次主导欲望。
9. 探索类欲望标 `satisfiedBy:'novelty'`，不要用行为硬凑。
10. **耗时匹配语义**：交谈 2-3 拍、冲突 3-5 拍、休息 6-10 拍、瞬时动作 1 拍；过短则无时序感，过长则全场等待。
11. 至少 1 个行为依赖场地（`requireEnvTypes`）且该场地需跨门可达，让「门与路径」参与剧情。

### 11.4 本地校验器 validateSchema

- **errors**（阻断）：引用完整性、数值域（min<max、default∈[min,max]）、ID 唯一、指派引用有效、**通道图连通性致命问题**（参演人物全部孤立）。
- **warnings**（不阻断）：违反 §11.3 各准则（含耗时缺失/越界）、孤立环境、无门（降级拓扑）、所有行为 `duration=1`（无时序感提示）。

## 16. 风险与应对

1. **通道布置负担**（每扇门都要画）→ 一键骨架 + 降级直连可先跑 + 孤立环境诊断；文档明确「先降级跑、看日志、再补门」的渐进流程。
2. **显式拓扑下人物全被困** → 启动前连通性检查 + 行为不可行时的「无路可走」限频事件 + 面板诊断常驻。
3. **时序过碎或过黏** → 耗时由架构师准则约束（§11.3.10）；行为分布统计 + 事件时间轴视图让失衡可见。
4. **叙事与事件脱节** → 逐事件覆盖要求 + 按事件数核对缺失提示。
5. **数值失衡（全员只做一件事）** → 校验 warnings + 分布统计 + §7.4 调参表。
6. **世界模型过度工程** → v1 锁死：无 A*、无障碍绕行、无昼夜、无常量编辑；门条件（钥匙）v2。
7. **会话与人物库漂移** → `stateFingerprint` 校验 + 恢复提示重置。
8. **性能** → 引擎在 store 外循环、按批写回；决策 O(actors×behaviors)、寻路图规模小（几十节点）；日志环形 500。
9. **正文上下文膨胀** → 脚本块 cap 2400 + 槽位上限 2 + 已删脚本忽略。
10. **复杂度蔓延** → v1 明确不做：A*/障碍绕行、昼夜与真实时长、门钥匙条件、打断与加入动作、多舞台、关系数值化、任意事件注入、推演写回画布/人物库、agent 向舞台投放。

## 18. 一句话备忘

剧情推演模拟器 = 作品内固定的舞台画布（沙盒，可从卷画布连同**通道**一键镜像布局）+ 系统内置世界模型（空间/**门与路径拓扑**/感知/移动/观察/交互/新颖度）+ 作品级欲望层（一切叙事需求翻译成人物的欲望）与行为层（满足手段，含**耗时**与独占占用）+ 本地 seeded 节拍引擎沿时间轴推进，多人在同一时间窗内重叠、排队、争抢，涌现带时间跨度的结构化事件链 + LLM 低频批量叙事化 + 指定主视角的事件链沉淀为剧情脚本 + 章节槽位引用后以【剧情脚本】既定事件块注入正文生成——空 schema 也能先跑、可复现、与自上而下流程并行互补。
