# 剧情推演模拟器设计 · 设计稿（待开发）

> 状态：**设计稿**（2026-10-29 起草，同日四次修订，未经实现）。本文回答「是什么、为什么这样设计、落在哪里」，实现前需过一遍 §17 待确认决策（新增 D24-D28 见 §19.9）。
> 定位：与现有「自上而下」创作流程（目标 → 规则 → 卷 → 大纲 → 正文）并列的第二种模式——**自下而上**：人物在**独立舞台画布**上按世界模型自主行动，剧情从模拟中涌现，作者观察、挑选、记录成剧情脚本，再交给正文生成。
> 前置阅读：[人物编辑库设计](人物编辑库设计.md)、[章节画布与人物状态设计](章节画布与人物状态设计.md)。

## 1. 需求

用户原始诉求（四轮）：

> ① 整个小说作品的构建过程基本是自上而下的搭建，我现在需要另外一种模式，可以从下而上地搭建。这是一个剧情推演模拟器：所有在场人物会进入实时模拟状态，可以指定人物记录其行为过程和事件链，作为剧情脚本，用于生成正文。在当前的系统之上，首先对人物有额外的要求，例如有扩展属性，有根据作品需求定义的不同欲望，在不同属性和欲望下产生的行为。同时需要一个系统层面的 skill，用于构建这些属性和行为的定义，使其数值架构合理、运行时能涌现内容。
>
> ② 这个模块需要一个**独立的画布**，与卷画布并列，可以称为**舞台**或**演播室**。其次，需要一个**基础世界模型**，能支持人物执行基础逻辑，例如移动、观察、感知。所有作品需求都在更高一层，统一视为**欲望层**——不同的作品为不同的人物添加特殊的欲望，例如探索欲、生存欲、爱情欲等等。
>
> ③ 当前的环境系统**没有路径和门的概念**，这在推演环境中是个大问题，需要补充。人物的**移动、行为都需要耗时**，以产生多人、多个行为的时序性。
>
> ④ **当前的人物属性结构不变**，但需要一个推演模拟器属性，这套属性与人物挂钩：创建张三时自动创建张三的基础信息数据（即当前的人物属性信息），同时还有一个张三的**推演器信息**，里面包含基础世界模型所需要的基础能力、可添加的欲望属性、行为列表。**两套数据要分离，可以各自单独迭代。**

分解为九条可实现的诉求：

1. **独立舞台画布**：与默认主画布、各卷画布并列的专属画布，模拟只在这里发生。
2. **两套数据分离**：人物档案（文本身份）与推演档案（数值）物理分开、各自演进，只通过 characterId 关联，人物创建时自动建推演档案。
3. **基础世界模型**：系统内置的空间 / 拓扑 / 感知 / 移动 / 观察 / 交互原语。
4. **基础能力**：世界模型原生参数（移动速度 / 感知范围 / 观察力）每人物一份数值，是「角色物理差异」的来源。
5. **路径与门**：显式连通拓扑——通道决定能不能过、绕多远，门可以锁。
6. **耗时与时序**：移动按距离耗时、行为按拍数耗时；多人动作重叠、排队、争抢，事件带时间跨度。
7. **欲望层 + 行为层**：作品级定义库（欲望/行为模板）+ 人物档案实例（每个张三想要什么、能做什么）。
8. **实时模拟**：舞台人物按节拍自主决策，可暂停、单步、干预；可指定人物记录行为过程与事件链。
9. **剧情脚本 → 正文 + 数值架构师技能**：事件链沉淀为脚本供正文消费；系统级技能辅助构建定义，使数值架构合理、运行时涌现。

### 2.2 缺口

1. **无独立舞台**：板全部派生自卷或主画布；舞台不加标记会落进 orphan 分支。
2. **人物无推演数据**：`CharacterState` 只有文本段与 `age:number`，没有任何数值槽、能力槽、欲望/行为槽——且按本轮需求，这些**不应塞进人物档案**，需独立数据集。
3. **环境无拓扑**：只有几何与嵌套，没有「哪两个环境能走、怎么走、门是否锁」——直线移动等于穿墙。
4. **无时间模型**：无 tick；动作瞬时完成，无法产生多人行为的重叠与先后。
5. **无世界模型运行时**：无感知范围、观察揭示、知识状态；`Math.random` 仅 3 处且全是 ID 生成，无 seeded RNG。
6. **无结构化事件日志与脚本产物**：大纲「事件链」是文本模板；输出通道只有设定块/写入块/正文。

## 3. 总体架构

```
┌─ 数据层（两套数据，物理分离，各自迭代）─────────────────┐
│ 人物档案  WorkCharacter/CharacterState（既有，不变）     │
│          姓名/性别/年龄/basicInfo/identityInfo/relations │
│ 推演档案  SimProfile（新增）                             │
│          基础能力 / 属性初值 / 欲望实例 / 行为列表        │
│          创建人物时自动生成；只通过 characterId 关联      │
│ 定义库    SimPlaySchema（作品级）                         │
│          属性定义 / 欲望定义 / 行为定义（可复用模板）      │
└──────────────────────────────────────────────┘
        ↓ 舞台参演时实例化为运行时 actor
┌─ 舞台画布（作品内固定一张，kind='stage'）───────────────┐
│ 环境布局 + 通道（门/路径）+ 人物放置 = 推演的物理世界     │
└──────────────────────────────────────────────┘
        ↓
┌─ L0 世界模型（系统内置，不可编辑）──────────────────────┐
│ 空间：环境嵌套树 + 几何                                 │
│ 拓扑：通道图（门/路径/窗），可锁；显式拓扑 or 降级直连    │
│ 感知：同环境互见（距离=人物 capabilities.perception）+ 进行中动作可见 │
│ 移动：沿通道图寻路，逐 tick 推进（人物 capabilities.speed）│
│ 观察：observe 原语（人物 capabilities.observation）      │
│ 交互 / 新颖度信号                                       │
│ 常量只提供默认值，实际取值来自人物推演档案                │
└──────────────────────────────────────────────┘
        ↓ 原语之上；一切动作占用时间
┌─ L1 行为实例（来自推演档案的行为列表）──────────────────│
└──────────────────────────────────────────────┘
        ↓ 行为服务于
┌─ L2 欲望实例（来自推演档案的欲望列表）──────────────────│
└──────────────────────────────────────────────┘
        ↓ 时间轴推进（tick）
┌─ 事件链（带 startTick→endTick 的结构化 SimEvent）──────┐
└──────────────────────────────────────────────┘
        ↓ 事件段批量（低频 LLM，单向不回写）
┌─ 叙事（人物档案文本 + 推演数值合流）→ PlotScript → 【剧情脚本】块 → 正文
```

三条设计判断：

- **两套数据分离**（D20）：人物文本是长期创作资产，推演数值是可反复调参的实验对象；混在一起会出现「调数值改坏人设」「改人设丢数值」。物理上分成两个 map，各有 sanitize、编辑入口与演进节奏，只在叙事化时只读合流。
- **世界模型固定、欲望开放**（D13）：移动/观察/感知/门不让作者定义，内置成能力层；作品只定义「人物想要什么、为此做什么」。
- **时间是一等公民**（D18）：动作有耗时与占用，事件带时间跨度——时序性是剧情感来源，不是事后排的。

## 4. 舞台画布（独立演播室）

### 4.1 定位与生命周期

- 作品内**固定一张**：`id='stage'`，`kind='stage'`；与默认主画布、卷画布 tab 并列（「🎬 舞台」）。
- 不参与卷派生，**不可删除**，只能「清空舞台」。
- **布局导入**：任意画布可「复制布局到舞台」——`planBoardCopy` mirror 语义（同人物放置 + 环境 + **通道**，`edges` 已按端点复制）。
- **不进章节体系**：不参与章节区域、快照自动同步、编辑 Agent 画布索引。

### 4.2 数据模型改动

```ts
// types/sim.ts — SimBoard 增加可选标记（additive）
export interface SimBoard {
  id: string;
  kind?: 'stage';          // 🎬 'stage' = 推演舞台；缺省 = 主画布/卷画布
  volumeId?: string;
  nodes: SimNodeType[];
  edges: Edge[];           // 'portal' 类型的边承载环境通道（§5.2）
  regions: ChapterRegion[];
  viewport?: SimViewport;
}
```

```ts
// boardOps.ts
export const STAGE_BOARD_ID = 'stage';
export const STAGE_BOARD_LABEL = '🎬 舞台';
export function stageBoard(): SimBoard { return { id: STAGE_BOARD_ID, kind: 'stage', nodes: [], edges: [], regions: [] }; }
```

五处配套：

1. `sanitizeBoards`（studioStore.ts:475-478 卷补板同处）：始终保证舞台板存在且 `kind:'stage'`。
2. `boardLabel`（boardOps.ts:33）：舞台常量优先。
3. `StudioPage.tsx:411-418`：`knownBoardIds` 加入 stage；tab 渲染。
4. `resolveBoardRef`（boardOps.ts:63）：**不认**舞台（agent 不可投放，D15）。
5. `clearLiveWork`：舞台由 sanitize 保证存在，清空作品 = 空舞台。

「清空舞台」= 清节点 + 通道 + session（人物库与推演档案保留）。

### 4.3 参演与记录

- **参演人物** = 舞台人物放置全集；推演入口只在舞台 tab 常驻。
- 启动时冻结：参演名单 + 当前状态 + 初始位置 + **推演档案快照**（能力/属性/欲望/行为）→ `SimPlaySession.actors`（含 `stateFingerprint` 供漂移检测）。
- running 时舞台只读；paused 可编辑（提示「修改在下次重置后生效」）。
- **记录人物**：1 个主视角必选 + 可选旁观者（`recordedCharacterIds: string[]` 留位，v2 多视角）。

## 5. 世界模型 L0（系统内置，不可编辑）

`src/engines/simWorldModel.ts`，纯函数 + 默认常量：把画布几何与通道翻译成「谁看得见谁、能不能走、要走多久、观察能揭示什么」。

### 5.1 空间

- 消费环境嵌套树（`parentId` 容器）；`item` 非容器。
- 人物运行时位置：`{ x, y, envId }`——绝对坐标供 overlay，`envId` 由几何每 tick 重算（复用 `findContainerAt`）。
- 初始位置由放置节点坐标换算。

### 5.2 拓扑：门与路径

**载体**：通道 = React Flow 边（`type:'portal'`），域属性存 `edge.data`。`edges` 已被渲染/复制/剪除/存档，只是从未有创建入口；用户「两点连线」即建通道。

```ts
export interface SimPortalData {
  kind: 'door' | 'path' | 'window' | 'gate';
  name?: string;          // 「后门」「密道」「窗台」
  locked?: boolean;       // 阻断通行（导演干预可开关）
  traverseCost?: number;  // 通行额外耗时（tick），默认 door/path=0，gate=1
  oneWay?: boolean;       // 单向（默认双向）
}
```

**渐进式拓扑**（D17）：

| 模式 | 条件 | 规则 |
| --- | --- | --- |
| **显式拓扑** | 板上 ≥1 条 portal | 只有通道连接的相邻环境可走；锁闭/单向断开；跨环境必须沿图寻路 |
| **降级直连** | 0 条 portal | 父↔子、同父兄弟全连通（无墙）；面板黄条提示「未布置通道」 |

- **一键骨架**：为每个子环境与父环境生成门（星形走廊）。
- **孤立环境诊断**：进入舞台时做连通性检查，列出不可达环境；推演中目标不可达 → 行为不可行 + 「无路可走」限频事件。
- **删除联动**：删环境时现有逻辑自动剪边（studioStore.ts:1619）；sanitize 丢弃端点非环境的 portal。
- **通用性**：通道属环境系统（任意画布可画可存），v1 只有推演消费。

### 5.3 感知

| 层 | 规则 | 得知内容 |
| --- | --- | --- |
| **直接感知** | 同 `envId` 且距离 ≤ 该人物 `capabilities.perception` | 姓名 + 可见状态 + **进行中的动作**；环境名/类型/描述 |
| **环境感知** | 同父兄弟环境或父容器 | 环境名称与类型，不知内部有谁 |
| **记忆感知** | 知识里已记录的内容 | 上次观察结果，**可能已过时** |

- 感知被动、每 tick 更新；进行中动作可见是「推门撞见」的机制基础。
- 跨容器不感知（窗通道 v2 可允许互见）。

### 5.4 移动与寻路（耗时）

- **寻路**：图上 BFS 最短跳数；锁闭/单向按方向过滤；同环境内无需路径。
- **路点**：逐段行走——走到通道中点（近似：两环境中心连线中点）→ 穿越 → 下一环境 → 目标中心。
- **耗时**：每 tick 推进该人物 `capabilities.speed` + 穿门 `traverseCost`。跨城镇自然比跨房间慢——**空间距离获得时间意义**。
- 移动中 `moving` 不决策；到达产生「到达」事件（低权重可关）。
- **不可达**：行为不可行，改选次优或原地兜底。
- 不做 A* 与障碍绕行（通道图已表达通行性）。

### 5.5 观察（observe）

- 系统原语行为，不可删除：耗时 ≈ `OBSERVE_BASE / 人物 observation`（默认 1 tick）观察当前或相邻环境 → 揭示环境/人物/物品/进行中动作 → 写入知识 → 低权重事件「X 在 Y 张望」。
- 探索类欲望的主要满足通道（§5.7），也是空定义时的保底动作。

### 5.6 交互

- 同环境、互见者才能发生 `requireCompanion` 行为；目标 = 互见者中相关欲望最强者。
- **目标必须空闲**（他人 `acting`/`moving` 时不可被瞄准）→ 多人互动天然排队。
- 行为正 `desireEffects` 传播给目标 → 冲突链。

### 5.7 新颖度

```ts
export interface SimKnowledge {
  knownEnvIds: string[];
  knownActorIds: string[];
  observedAt: Record<string, number>;
}
```

新到达环境 + 新观察到的人物/环境 → 对 `satisfiedBy:'novelty'` 的欲望按 `noveltyRelief`（默认 25）缓解。探索欲因此不必由作者硬写行为。

### 5.8 空定义兜底

无欲望/行为实例时，以 `idleWeight` 驱动原语：张望 → 沿通道走向未到过的环境 → 再张望。先跑起来再调参。

### 5.9 默认常量（仅作人物能力缺省值）

`PERCEPT_RANGE 400 / SPEED 80 / ARRIVE_EPS 12 / OBSERVE_BASE 1 / NOVELTY_RELIEF 25 / IDLE_WEIGHT 1`——**这些是世界模型的默认值，实际运行取人物推演档案的 capabilities**（§6.4）。面板「世界模型」页只读展示默认值与当前人物实际值区间。

## 6. 两套数据：人物档案 vs 推演档案

### 6.1 分离原则（D20）

| | 人物档案（既有，不变） | 推演档案（新增） |
| --- | --- | --- |
| 类型 | `WorkCharacter` / `CharacterState` | `SimProfile` |
| 存放 | `SimState.characters` | `SimState.simProfiles`（独立 map） |
| 内容 | 姓名/性别/年龄/basicInfo/identityInfo/relations/形象 | 基础能力 / 属性初值 / 欲望实例 / 行为列表 |
| 语义 | 叙事身份（给读者看的人） | 数值行为（给引擎跑的人） |
| 编辑入口 | 人物库 / 检查器（既有） | 推演面板「人物档案」 |
| 演进 | 独立 sanitize、独立版本、独立脏检查项 | 同左 |
| 关联 | 仅 `characterId`（+ 可选 `stateId` 覆盖） | 同左 |

- **自动创建**：`createCharacter` 时同事务创建默认 `SimProfile`（能力取世界模型默认；欲望/行为取定义库当前全集并启用；属性取定义默认值）。
- **删除联动**：`deleteCharacter` 同时删档案；`mergeCharacters` 保留主人物档案（其余随人物删除），面板可提示「被合并人物的独特欲望未迁移」；sanitize 清理孤儿档案（无对应人物的档案例）。
- **各自迭代**：改文本不影响数值；调数值不触发人物档案脏写（两 map 分开比较，`sameStudioContent` 各加一项）。
- **合流点只有一个**：叙事化时只读合并（人物卡 = 文本 + 当前数值），推演结果也不回写人物档案。

### 6.2 作品级定义库（SimPlaySchema）

```ts
export interface SimPlaySchema {
  version: 1;
  attributes: SimAttributeDef[];   // 扩展属性定义（体力/理智/灵力…）
  desires: SimDesireDef[];         // 欲望定义模板
  behaviors: SimBehaviorDef[];     // 行为定义模板
}
```

- 定义库是「模板/调色板」，人物档案是「实例」；实例以 `defId` 引用。
- **修改定义 → 所有引用它的实例跟随**（写一处全局生效，与人物库哲学一致）；**删除定义 → 校验器报错 + 面板提供清理**（实例失效不静默删，告知后由用户确认）。
- **新增定义默认不同步到已有档案**（D22），面板提供「同步到全部人物」一键——避免作者正在调参时被新模板打乱。

### 6.3 基础能力（世界模型原生，固定集合）

```ts
export interface SimCapabilities {
  /** 移动速度（px/tick），默认 80 */
  speed: number;
  /** 感知范围（px），默认 400 */
  perception: number;
  /** 观察力（0-100），默认 50；观察耗时 = OBSERVE_BASE / (0.5 + observation/100) */
  observation: number;
}
```

固定三项、不可增量扩展——它们是世界模型的物理参数（跑得快、看得远、观察敏锐），作者只调数值不定义语义。语义化的「扩展属性」（体力/理智/灵力）留在定义库的 `attributes` 里，供行为门槛与消耗使用（§6.5）。

## 7. 时间与节拍引擎

`src/engines/simPlayEngine.ts`，纯函数，由 store 外定时循环驱动 `step()`，按批写回。

### 7.1 时间模型

- **tick = 基本时拍**（叙事上约 1-2 分钟，UI 不展示，由叙事化层转译）。
- **动作有耗时**：行为 `duration`；移动按距离/速度跨多拍；穿门 `traverseCost`。
- **状态机**：`idle → moving → acting(until endTick) → idle`。忙碌者不决策、不可被互动瞄准；效果完成时一次性结算。
- **同拍并发**：按 `characterId` 排序（seed 平局）确定性执行；互斥占用与「目标须空闲」使第二人不可行 → 换次优 → 「受阻」事件。
- **事件带时间跨度**：`SimEvent { startTick, endTick, status:'doing'|'done'|'blocked' }`；日志 `[t3→t7]`；进行中动作可被感知。
- **时序三来源**：耗时重叠 / 排队互斥 / 移动晚到。
- 推演速度 = 每拍真实毫秒（0.5/1/2/5s），与故事时间无关。

### 7.2 tick 流程

1. **位置推进**：`moving` 者前进 `capabilities.speed`；抵达路点/目标切换；到达产生事件。
2. **动作完成**：`acting` 且 `endTick == tick` → 结算 effects → 完成事件 → `idle`。
3. **感知更新**：直接/环境感知（含他人进行中动作）→ `knowledge`。
4. **新颖度结算**：新环境/新面孔 → novelty 缓解。
5. **欲望演化**：`clamp(intensity + growthPerTick)`。
6. **冷却递减**。
7. **决策（仅 idle）**：§7.3 评分；无可用行为 → 原语兜底。
8. **开始动作**：算路径与耗时 → `action{startTick, endTick}` → 开始事件；移动意图先 `moving`。
9. **事件剪枝**：环形 500。

### 7.3 效用评分

```
score(b) = Σ_d [ intensity(d) × max(0, −effect_b(d)) ]
         + Σ_n [ intensity(n) × noveltyRelief × noveltyHit_b ]
         × feasibility(b)      // 属性门槛 × 场地 × solo/companion × 目标空闲 × 路径可达
         × weight(b) × cooldownGate(b) × noise    // noise∈[0.9,1.1] seeded
```

- 属性只做门槛与消耗，不进效用。
- 加剧型行为不产生效用，靠权重与传播制造剧情。
- **可复现**：`mulberry32(seed)`，按 `(tick, actorId)` 派生子种子；同 seed + 同定义 + 同档案 = 逐拍一致（测试硬断言）。

### 7.4 涌现从哪来

| 机制 | 设计着力点 |
| --- | --- |
| 欲望冲突 → 摇摆 | 至少一对欲望效果互斥 |
| 世界信号 → 自发行动 | 探索欲 × 未知环境；生存欲 × 低体力 → 回家 |
| 门与路径 → 戏剧门槛 | 锁门断路 → 绕远/被困/错过；远距离 → 迟到 |
| 时间重叠 → 撞见 | 耗时而进行中动作可见 → 「推门看见」 |
| 竞争 → 排队受阻 | 互斥占用、目标忙碌 → 次优行为与受阻事件 |
| **能力差异 → 差异化行为** | 跑得快的人先到、观察力强的人先发现、感知远的人先察觉 |
| 阈值错拍 | threshold 错开 ≥20% |
| 互动传播 | 加剧行为传染，单人物冲动变多人冲突链 |
| 记忆过时 | 按旧印象行动 |
| 冷却节奏 | 冷却长短本身是节奏设计 |

### 7.5 运行模式

自动循环（0.5/1/2/5s）+ 手动单步，共用 `step()`（D9）。

## 8. LLM 叙事化层

## 11. 系统级技能：数值架构师

### 11.1 定位

**不进用户写作技能库**。形态照 `memoryTemplates`：系统内置规范 = 推演面板「AI 构建设计」按钮的 system 提示 + 产出协议块。

### 11.2 输入与产出

### 11.3 设计准则（系统提示硬性要求）

1. 欲望 3-5 个，至少一对张力对。
2. 每欲望 ≥2 个满足行为（不同场地/条件）。
3. ≥1 个阈值属性做门槛。
4. 各欲望 threshold 错开 ≥20%。
5. 单行为对单欲望缓解量 20-40。
6. ≥2-3 个无门槛保底行为。
7. ≥2 个行为依赖他人在场。
8. `growthPerTick` 按节奏反推：20-40 拍触发一次主导欲望。
9. 探索类欲望标 `novelty`。
10. 耗时匹配语义：交谈 2-3、冲突 3-5、休息 6-10、瞬时 1；过短无时序感，过长全场等待。
11. ≥1 个行为依赖需跨门可达的场地，让门与路径参与剧情。
12. **能力差异化**：不要全员同速同感知——至少一个跑得快、一个看得远，让时序产生人物差异。

### 11.4 本地校验器 validateSchema

- **errors**（阻断）：引用完整性（定义库/档案实例双向）、数值域、ID 唯一、通道连通性致命问题（全员孤立）。
- **warnings**（不阻断）：违反 §11.3（耗时缺失/越界、能力全员相同、孤立环境、降级拓扑、所有 duration=1）。

## 16. 风险与应对

1. **两套数据不同步/漂移**（人物删了档案还在、档案引用已删定义）→ sanitize 孤儿清理 + 校验器双向引用检查 + 面板「缺档案/失效引用」可见。
2. **通道布置负担** → 一键骨架 + 降级直连可先跑 + 孤立环境诊断。
3. **显式拓扑下全员被困** → 启动连通性检查 + 「无路可走」限频事件。
4. **时序过碎或过黏** → 架构师准则 §11.3.10 + 时间轴视图 + 分布统计。
5. **叙事与事件脱节** → 逐事件覆盖 + 数量核对提示。
6. **数值失衡** → 校验 warnings + 分布统计 + §7.4 调参表。
7. **世界模型过度工程** → v1 锁死：无 A*、无障碍绕行、无昼夜、无常量编辑；门钥匙条件 v2。
8. **档案与 session 漂移**（推演中改了档案）→ 会话冻结档案快照 + `stateFingerprint`；修改在下次重置生效。
9. **性能** → store 外循环按批写回；O(actors×behaviors)；小图寻路；日志环形 500。
10. **正文上下文膨胀** → 脚本块 cap 2400 + 槽位 2。
11. **复杂度蔓延** → v1 不做：A*/绕障、昼夜真实时长、门钥匙、打断与加入、多舞台、关系数值化、任意事件注入、推演写回、agent 向舞台投放。

## 19. 修订四：统一标签内核（精简 × 扩展的准入标准）

> 2026-10-29 第四轮讨论结论（**已实现并修订**：同日先完成垂直切片，随后按用户要求把内核改为**零内置内容**——示例题材全部移出引擎，补齐作品级定义库、通道拓扑、时间相位、认知与有向关系；实现记录见 §19.11）。前三轮回答「怎么跑起来」，本轮回答「怎么在不变臃肿的前提下持续长大」。
> 问题陈述：既要系统足够精简，又要能匹配不同作品（都市、修仙、悬疑、校园、历史……）的需求。

### 19.1 两条目标与一条判据

- **精简** = 内核的**概念数固定**，不随题材/作品增长。
- **扩展** = 新增一部作品或一个题材，**引擎 0 行代码**，只加数据。
- 判据：任何新需求先归类——**内容是数据，机制是原语**。需要新原语 = 一次显式的架构决策，必须评审 + 测试，不得顺手添加。

### 19.2 内核 = 5 个维度 + 6 种原语 + 1 条管线 + 1 套刻度

**5 个维度（状态；引擎只认识这些）**

| 维度 | 内容 | 现状 |
| --- | --- | --- |
| 空间 | 环境树（社区/城镇/建筑/房间/床/物品）+ 通道边（门/路径/锁/耗时） | 数据已有（`ENV_TYPES` + `parentId` + edges），引擎未消费 |
| 时间 | 拍（§7.1）；可选昼夜四相（D26） | 拍已有；相位待定 |
| 实体 | 人物 / 环境 / 边，各自携带标签实例 | 标签层待建 |
| 认知 | 每个 actor 的已知标签与 `seenTick`（**可以过时**） | 仅 `knownEnvIds`，需扩展 |
| 关系 | 人物之间带标签与数值的边（亲缘/爱慕/敌意/信任） | 无（S6） |

**6 种原语（引擎代码固定理解；标签只能映射到它们）**

| # | 原语 | 做什么 | 标签如何消费 | 例子 |
| --- | --- | --- | --- | --- |
| 1 | 移动 | 模式 + 速度 + 通行性 | `grant/revoke move:walk\|fly\|wheelchair` | 残疾 = revoke walk；御剑 = grant fly（无视通道拓扑） |
| 2 | 需求 | 0-100 + 增长 + 阈值 + 缓解 | need 标签 | 饥饿、口渴、疲劳 |
| 3 | 情绪 | 0-100 + 衰减 + 候选效用倍率 | emotion 标签 | 恐惧→远离源；害羞→社交权重下降 |
| 4 | 交互 / affordance | 目标 + 前置 + 耗时 + 效果 + 占用 | 环境/边 affordance 标签 | 冰箱=提供食物，浴缸=可洗，门=可通行 |
| 5 | 感知 | 可见性（always/near/concealed）+ 半径 + 发现事件 | trait 的 `visibility` | 西装总是可见；手枪需靠近/张望才发现 |
| 6 | 反应 | 观察到标签 + 条件 → 情绪Δ + 行为偏置 | `reacts` 规则 | 喜欢西装→靠近；发现枪→恐惧+远离 |

**1 条决策管线**：四层（紧急 / 常规 / 社交·环境 / 待机）+ 紧急层抢占 + 意图记忆（§19.4）。
**1 套刻度**：全部状态 0-100，UI 显示文案档（不饱/略饿/很饿…）。**不做第二套刻度**（0-5、0-10 一律不引入）。

### 19.3 统一标签：两种载体、五种角色

数据模型只剩两种载体：**实体**（人物 / 环境 / 边）与**关系**（人物↔人物边），都携带标签实例。属性、欲望、物品、情绪不再各自成为概念：

| 旧概念 | 统一后 | 说明 |
| --- | --- | --- |
| 属性（残疾/会御剑） | trait 标签 + 原语参数 | 只有"许可/参数"，不做数值对抗 |
| 欲望（饥饿…） | need 标签 | **沿用现有 `SimProfile.desires` 的 0-100 与阈值**，不另起系统 |
| 情绪（害怕…） | emotion 标签 | 新增；短衰减；只影响候选效用 |
| 物品/衣着（西装/手枪） | 携带者上的 trait 标签 | 无库存、无实例、无装备槽；转移 = 增删标签 |
| 环境物件（冰箱/浴缸/垃圾） | 环境标签 | 核心 affordance 或纯叙事标签 |
| 关系（喜欢/敌意） | 人物边的标签 + 数值 | 作品级稀疏图（S6） |

定义与实例（示意）：

```ts
interface SimTagDef {
  id: string; name: string;
  scope: 'character' | 'env' | 'edge';
  role: 'trait' | 'need' | 'emotion' | 'affordance' | 'narrative';
  grants?: { move?: { mode: 'walk' | 'fly' | 'wheelchair'; speed?: number }; affordances?: string[] };
  revokes?: string[];                        // 撤销的能力 id
  need?: { initial: number; growth: number; threshold: number; relief: number };
  affect?: { decay: number; bias: Partial<Record<BehaviorCategory, number>> };
  visibility?: 'always' | 'near' | 'concealed';
  reacts?: ReactionRule[];                   // 观察到该标签时的反应
  narrative?: string;                        // 只进叙述，不进决策
}
interface SimTagInstance { defId: string; value?: number; state?: 'ok' | 'depleted' | 'locked' | 'occupied'; }
```

两条硬语义：

1. **撤销显式**：`disabled` 写 `revokes: ['move:walk']`，不能靠"没写移动标签"来表达——否则分不清"作者没填"和"故意没有"。多标签冲突时 **revoke 优先**，校验器给警告。
2. **能力是许可，不是数值对抗**：会御剑就是能飞，不需要"修为 80 vs 60"、等级、伤害。不确定性交给叙事层；一旦引入判定/成长/战斗，就是游戏，不在内核。

### 19.4 四层决策管线

参考游戏原型图的「自检 → 降级 → 待机自检」，固定为四层（层间硬优先，层内按 §7.3 效用）：

```
每拍（idle，或被紧急层抢占）：
  0. 忙碌中：只有紧急层允许抢占（带冷却，防抖）
  1. 紧急层：need ≥ emergency 或 emotion ≥ break → 只能救急
  2. 常规层：utility(§7.3) × 标签可用性 × 关系/情绪权重
  3. 社交·环境层：同场人物可互动 / 环境 affordance 可用
  4. 待机层：无候选 → zoneOut / 小范围走动
```

- **候选来自标签索引**（环境标签、同场人物、关系、可用能力）：每人每拍 5-20 个，与定义总数无关——这是"上百个行为"不拖垮性能的关键。
- **意图记忆**：动作被中断时存 `pendingIntent`，恢复时优先回溯，不每拍重新掷骰。
- 硬优先层防止"饿死也不吃饭"被其他高权重行为压住；层内仍用效用与 seeded 噪声制造变化。

### 19.5 扩展阶梯与五道契约

| 级别 | 改动内容 | 成本 | 例子 |
| --- | --- | --- | --- |
| L0 | 新标签 / 行为定义 | **0 行引擎代码** | 西装、手枪、御剑、辟谷 |
| L1 | 新反应规则 / 题材包 | **0 行引擎代码** | 修仙包、都市悬疑包 |
| L2 | 新原语 | 代码 + 显式评审 | 战斗、经济、真实日程 |
| L3 | 新子系统 | 不做 / 分叉 | 技能树、地图编辑器 |

**契约**（以后每个功能都过这五条）：

- **C1 引擎不知道题材**：源码不得出现题材分支（无 `if (修仙)`），题材差异只能是数据。
- **C2 准入校验**：未知标签/行为一律拒绝；每个定义必须有消费者（行为或感知），否则降级为叙事标签；revoke 优先。
- **C3 叙事只读**：LLM 只读"文本 + 数值"合流，不回写状态。
- **C4 预算**：每实体核心标签 ≤ 8；每拍候选 ≤ 20；反应规则 ≤ 50；人物知识 ≤ 64 条；每环境运行时态只有固定几个字段（占用/耗尽/锁闭/脏污/冷却）。
- **C5 确定性**：同 seed + 同标签集 = 同结果；标签顺序不得影响决策（排序后再计算）。

**内核零内容（C1）**

- 引擎只消费 6 个原语（移动/需求/情绪/交互·affordance/感知/反应）与 5 个维度（空间/时间/实体/认知/关系），代码中不含任何题材常量或分支。
- 定义全部来自作品级 `SimSchema`（`src/types/sim.ts`，逻辑在 `src/stores/simSchema.ts`）：
  - `SimTagDef{id,name,icon?,desc?,scope:'character'|'env'|'relation',role:'trait'|'need'|'emotion'|'affordance'|'narrative',visibility?,revokes?,grantsMove?,need?,emotion?,affordance?,narrative?,stance?}`；
  - `SimReactionDef{triggerScope,triggerTag,selfTag?,emotion?,need?,stance?,text?,cooldown?,priority?}`；
  - `SimRelationDef{name,stance,minValue?,maxValue?,talkDuration?,talkDistance?,priority?}`；
  - `SimTimeDef{ticksPerDay,phases[{id,name,from,to}]}`（缺省单相「全天」，120 拍/天）。
- **空 schema = `{tags:[],reactions:[],relations:[]}`**；新作品/旧档缺失一律为空，旧档里的题材标签随 sanitize 丢弃（预期）。示例定义只存在于测试夹具与本文档。
- 预算（C4）：标签 ≤128、反应 ≤50、关系定义 ≤16、人物标签 ≤8、环境标签 ≤4、关系标签 ≤3、认知 64 条/人、候选 ≤20。sanitize 拒绝未知/悬空引用（C2），全部排序遍历保证同 seed 可复现（C5）。
- 动作内建为 6 种：`idle / move / observe / interact / social / avoid`；删除「逐人物行为列表」，行为不再可配置。

**数据模型**

- `SimProfile{characterId,capabilities{speed,perception,observation},tags,needs}`：只存实例与覆盖参数，删除 `attributes`/`behaviors`；`defaultSimProfile` 按 schema 为每个 need 建默认实例；运行时 `resolveSimProfile` 合并「定义默认 ← 档案实例」。
- 环境标签在 `EnvironmentData.tags`；关系为**作品级有向多标签**：`SimRelation{from,to,tags,value?}`（value 0-100 默认 50；旧 `{a,b}` 无向档展开为双向），随存档 v4 持久化，删除人物/合并人物/载入/持久化全部级联清理。
- 定义增删改走 store：`upsertSchemaTag / deleteSchemaTag / upsertSchemaReaction / upsertSchemaRelationDef / setSimTime / replaceSimSchema(JSON) / exportSimSchema / syncSchemaToProfiles`；删除定义级联清理人物标签、环境标签、需求实例、关系标签与引用它的反应。

**空间（§5 通道拓扑）**

- `buildSimWorld(board)` 把环境节点抽成绝对坐标盒、把**环境↔环境**连线抽成通道 `{locked,oneWay,traverseCost,waypoint?}`。
- 0 条通道 → **降级直连**（父↔子 + 同父兄弟相邻）；≥1 条 → **显式拓扑**（容器间只经通道，父子内部自由）。
- 容器级 BFS 寻路；锁闭通道不可过；单向通道只顺向；`traverseCost` 作为过门等待；路点取通道中点。画布上四向 Handle + `ConnectionMode.Loose` 建通道，`SimPortalEdge` 显示门/锁；世界模型页可锁闭。
- 人物在画布上的移动由 React Flow 节点投影，推演不改写画布数据。

**时间（§19 D26）**

- 会话每拍计算 `clock{tick,day,phaseId,phaseName}`；相位为一天内 0-1 半开区间。
- `affordance.activePhases` 非空时只有相位命中才可用；不可用写入限频提示「现在不可用」。
- 设计页可编辑「一天多少拍 + 相位表」；世界模型页与推演条显示 `第 N 天 · 相位`（`data-sim-clock`）。

**认知与关系**

- `SimActor.knowledge{envs,actors}` 带 `seenTick`，超过 TTL 遗忘、重新感知才恢复；隐藏标签需靠近（≤150px）或张望才发现；环境首次进入触发叙事标签的 `discoverText`（只读日志 = C3）。
- 有向关系按 `from→to` 读取，stance 由关系定义决定（avoid 优先于 approach/talk）；`minValue/maxValue` 过滤、`talkDistance/talkDuration` 生效。

**UI**

- `SimPlayPanel` 三页：世界模型（舞台现状/时钟/通道/环境标签/接入状态/认知计数）、人物档案（能力/标签/需求/情绪/有向关系）、设计 · 定义库（`SimSchemaEditor`）。
- `SimSchemaEditor`：标签/反应/关系/时间四个分区 + JSON 导入导出 + 校验提示 + 级联删除；表单项按 role 显示；id 不可改（引擎引用）。
- 空定义库时各页只给空态与「去设计页」引导，不出现任何内置题材。
