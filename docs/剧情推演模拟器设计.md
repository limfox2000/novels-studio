# 剧情推演模拟器设计 · 设计稿（待开发）

> 状态：**设计稿**（2026-10-29 起草并修订，未经实现）。本文回答「是什么、为什么这样设计、落在哪里」，实现前需过一遍 §17 待确认决策。
> 定位：与现有「自上而下」创作流程（目标 → 规则 → 卷 → 大纲 → 正文）并列的第二种模式——**自下而上**：人物在**独立舞台画布**上按世界模型自主行动，剧情从模拟中涌现，作者观察、挑选、记录成剧情脚本，再交给正文生成。
> 前置阅读：[人物编辑库设计](人物编辑库设计.md)、[章节画布与人物状态设计](章节画布与人物状态设计.md)。

## 1. 需求

用户原始诉求（两轮）：

> ① 整个小说作品的构建过程基本是自上而下的搭建，我现在需要另外一种模式，可以从下而上地搭建。这是一个剧情推演模拟器：所有在场人物会进入实时模拟状态，可以指定人物记录其行为过程和事件链，作为剧情脚本，用于生成正文。在当前的系统之上，首先对人物有额外的要求，例如有扩展属性，有根据作品需求定义的不同欲望，在不同属性和欲望下产生的行为。同时需要一个系统层面的 skill，用于构建这些属性和行为的定义，使其数值架构合理，运行时能涌现内容。
>
> ② 这个模块需要一个**独立的画布**，与卷画布并列，可以称为**舞台**或**演播室**。其次，需要一个**基础世界模型**，能支持人物执行基础逻辑，例如移动、观察、感知。所有作品需求都在更高一层，统一视为**欲望层**——不同的作品为不同的人物添加特殊的欲望，例如探索欲、生存欲、爱情欲等等。

分解为六条可实现的诉求：

1. **独立舞台画布**：与默认主画布、各卷画布并列的一张专属画布，模拟只在这里发生，不污染任何卷画布。
2. **基础世界模型**：系统内置的空间 / 感知 / 移动 / 观察 / 交互原语——人物能「看见谁、走到哪、观察到什么」。世界模型不由作者编辑，是一套固定能力。
3. **欲望层**：作品的一切叙事需求统一翻译成欲望（探索欲 / 生存欲 / 爱情欲 / 复仇欲…）。欲望定义在作品级，可逐人物指派与调参。
4. **行为层**：作品级定义行为（满足欲望的手段），行为建立在世界模型原语之上。
5. **实时模拟**：舞台上的在场人物按节拍自主决策与行动，可暂停、单步、干预；可指定人物记录其行为过程与事件链。
6. **剧情脚本 → 正文**：记录下来的事件链沉淀为剧情脚本，供正文生成消费。另需系统级技能「数值架构师」辅助构建欲望/行为定义，使数值架构合理、运行时涌现内容。

| 编辑技能记忆模板 | `memoryTemplates.ts`（`skills/editor-memory/*.md?raw` 内联，固定小节+出厂基线） | **系统级内置规范的现有形态**——数值架构师技能照此实现，不进用户技能库 |

### 2.2 缺口

1. **无独立舞台**：现有板全部派生自卷或主画布；or 舞台若不加标记会落进 orphan 画布分支（`StudioPage.tsx:416-418`）。
2. **无世界模型**：环境只有静态几何与描述，没有感知范围/视野/移动步进/观察揭示等运行时语义；人物也没有「见过谁、去过哪」的知识状态。
3. **无欲望/行为数值体系**：人物属性除 `age: number` 外全是文本段；`Math.random` 仅 3 处且全是 ID 生成，无 seeded RNG。
4. **无模拟时间**：全仓库无 tick/节拍；`round` 只存在于一次性编辑会议（2-8 轮）。
5. **无结构化事件日志与脚本产物**：大纲「本章事件链」是文本模板；输出通道只有设定块/写入块/正文三种。

## 3. 总体架构：舞台 + 分层世界

```
┌─ 舞台画布（作品内固定一张，kind='stage'）───────────────┐
│ 环境布局 + 人物放置 = 推演的物理世界                    │
│ 可从卷画布一键镜像布局；推演结果不写回任何卷画布          │
└──────────────────────────────────────────────┘
        ↓ 参演（舞台上的放置 = 在场人物）
┌─ L0 世界模型（系统内置，不可编辑）──────────────────────┐
│ 空间：环境嵌套树 + 几何坐标                             │
│ 感知：同环境互见（距离过滤）+ 邻接环境名称模糊可见        │
│ 移动：moveToward 原语，逐 tick 步进，到达判定            │
│ 观察：observe 原语，揭示环境/人物/物品 → 知识           │
│ 交互：同环境互见即可互相作用；结束传播在行为层            │
│ 新颖度信号：新环境/新面孔 → 供探索类欲望结算             │
└──────────────────────────────────────────────┘
        ↓ 原语之上
┌─ L1 行为层（作品级定义）───────────────────────────┐
│ 行为 = 条件（属性门槛/场地/同伴）+ 效果（缓解欲望/消耗属性/ │
│ 加剧他人欲望）+ 移动意图                               │
└──────────────────────────────────────────────┘
        ↓ 行为服务于
┌─ L2 欲望层（作品级定义 + 人物指派）───────────────────┐
│ 探索欲/生存欲/爱情欲/复仇欲…（作品需求统一翻译成欲望）    │
│ 每 tick 增长；被行为或新颖度缓解；超阈值成为主导欲望      │
└──────────────────────────────────────────────┘
        ↓ seeded 节拍引擎（纯本地、零 API、可复现）
┌─ 事件链（结构化 SimEvent）──────────────────────────┐
└──────────────────────────────────────────────┘
        ↓ 事件段批量（低频 LLM，单向不回写）
┌─ 叙事化文本 → PlotScript 剧情脚本库 ─章节槽位→ 【剧情脚本】块 → 正文生成
```

三条设计判断：

- **世界模型固定、欲望开放**（决策 D13）：移动/观察/感知这类「基础逻辑」如果也让作者定义，等于让作者写游戏引擎——系统内置成不可编辑的能力层；作品只在上层定义「人物想要什么、为此做什么」。
- **数值决策 + LLM 叙事化**（决策 D1）：纯 LLM 驱动行动又贵又不可复现，纯数值又干瘪。数值层高频免费试错，叙事层低频生成文本，单向数据流。
- **舞台是沙盒**（决策 D8/D12）：推演位置只用 overlay 呈现，结束不动画布；产物只有剧情脚本。

## 4. 舞台画布（独立演播室）

### 4.1 定位与生命周期

- 作品内**固定一张**舞台画布：`id = 'stage'`，`kind = 'stage'`。与默认主画布、卷画布在 tab 栏并列（建议标签「🎬 舞台」）。
- 不参与卷派生（没有 `volumeId`），**不可删除**，只能「清空舞台」（清节点，保留空板）。
- 所有推演只发生在舞台画布上；舞台上的节点就是推演世界（环境 + 人物放置），与卷画布完全独立。
- **布局导入**：任意画布可「复制布局到舞台」——复用 `planBoardCopy` 的 mirror 语义（同人物放置 + 同环境结构），一次把某卷的舞台搬过来做推演底稿。反向（舞台 → 卷）v1 不做。
- **不进章节体系**：舞台板不参与章节区域（`ChapterRegion` 绑定章节，与卷画布一一对应）、不参与章节快照自动同步（`chapterSceneSync` 只认章节所属画布）、不进入编辑 Agent 的画布索引/检索（避免 agent 把人物放去舞台）——这些边界随「舞台板是模拟专用」成立。

### 4.2 数据模型改动（最小）

```ts
// types/sim.ts — SimBoard 增加可选标记（additive，旧存档天然兼容）
export interface SimBoard {
  id: string;
  /** 🎬 板类型：'stage' = 推演舞台；缺省 = 默认主画布/卷画布（既有语义不变） */
  kind?: 'stage';
  volumeId?: string;
  nodes: SimNodeType[];
  edges: Edge[];
  regions: ChapterRegion[];
  viewport?: SimViewport;
}
```

```ts
// boardOps.ts
export const STAGE_BOARD_ID = 'stage';
export const STAGE_BOARD_LABEL = '🎬 舞台';
/** 舞台板：固定 id，无卷 */
export function stageBoard(): SimBoard { return { id: STAGE_BOARD_ID, kind: 'stage', nodes: [], edges: [], regions: [] }; }
```

五处配套（按依赖序）：

1. `sanitizeBoards`（studioStore.ts:475-478 卷补板同处）：始终保证 `boards[STAGE_BOARD_ID]` 存在且 `kind:'stage'`；旧档无则补空板。
2. `boardLabel`（boardOps.ts:33）：`STAGE_BOARD_ID` → 「🎬 舞台」优先于 volumeId 分支。
3. `StudioPage.tsx:411-418`：`knownBoardIds` 加入 stage；tab 栏在默认主画布之后、卷画布之前渲染舞台 tab。
4. `resolveBoardRef`（boardOps.ts:63）：**不认**舞台——编辑 Agent/落地区块按卷名定位，v1 不允许 agent 向舞台投放（避免污染沙盒）。舞台成为 agent 目标留 v2 决策。
5. `deleteVolume` / `clearLiveWork`（Bookshelf）：不受影响（舞台板由 sanitize 保证存在，清空作品后是空舞台）。

「清空舞台」动作：`clearStageBoard()` = 移除舞台全部节点（人物放置清除，人物库记录保留）+ 清空 session。不做图片 GC（属库）。

### 4.3 参演与记录

- **参演人物** = 舞台板上的全部人物放置（`CharacterPlacementData`）。开始推演的入口按钮在舞台 tab 上常驻，卷画布上没有此按钮（或置灰提示「推演在舞台画布进行」）。
- 启动推演时把参演名单 + 各自当前状态（`activeStateId`）+ 初始位置（放置坐标 → 转换到父环境）冻结进 `SimPlaySession.actors`，session 里存 `stateFingerprint` 供恢复时漂移检测。
- 推演期间**锁定舞台编辑**（拖节点/改环境会在 UI 上提示「推演中，暂停并重置后才可编辑」）——v1 简单处理：running 状态下画布交互只读；paused 状态可编辑但提示「修改将在下次重置后生效」。
- **记录人物**：1 个主视角（必选）+ 可选若干旁观者（v2 扩展多视角脚本；v1 数据结构 `recordedCharacterIds: string[]` 已留位）。

## 5. 世界模型 L0（系统内置，不可编辑）

新文件 `src/engines/simWorldModel.ts`，全部纯函数 + 常量。作用：把画布几何翻译成「谁看得见谁、能不能走过去、观察能揭示什么」。

### 5.1 空间

- 直接消费环境嵌套树：容器类型（room/building/community/town/area/bed）构成包含关系，`parentId` 表达父子；`item` 是非容器物件。
- 人物的运行时位置：`{ x, y, envId: string }`——`x/y` 为画布绝对坐标（overlay 直接画），`envId` 为最近包含它的容器（引擎每 tick 依据几何重算，也即「站在哪个房间」）。初始位置由放置节点坐标换算。
- 容器归属判定复用现有 `findContainerAt`（`components/studio/StudioPage.tsx` 导入自 store，放置/拖入语义一致）。

### 5.2 感知

三层，从近到远：

| 层 | 规则 | 得知内容 |
| --- | --- | --- |
| **直接感知** | 同一 `envId` 且直线距离 ≤ `PERCEPT_RANGE`（默认 400px） | 对方是谁（姓名+可见状态标签）、环境名/类型/描述 |
| **环境感知** | 同父容器的兄弟环境，或父容器本身 | 环境名称与类型（模糊知悉「旁边有个房间」），**不知内部有谁** |
| **记忆感知** | 知识里已记录的环境/人物 | 上次观察时的名单与描述（可能已过时——这正是戏剧张力） |

- 感知是**被动**的、每 tick 自动更新；`knowledge.lastSeen` 记录「最近一次看见某人的 tick」与「最近一次观察某环境的 tick」。
- 边界：环境级感知不受距离限制（房间内一定知晓房间边界）；跨容器不感知。

### 5.3 移动

- 原语 `moveToward(targetEnvId)`：目标点 = 目标环境包围盒中心；每 tick 直线移动 `SPEED`（默认 80px/tick）；进入目标包围盒即到达（`ARRIVE_EPS` 容差）。
- 不做寻路（画布是示意地图，不是物理仿真）；跨容器直达（v1 简化），**穿过其它环境时不触发进入事件**（避免「路过」污染事件流；到达才算进入）。
- 移动本身不产生事件；到达时产生一条低权重事件「到达 X」（面板可关）。
- **由谁发起移动**：行为通过 `moveTargetEnvType` / `moveTargetEnvId` / 探索意图（去未知环境）声明目标；引擎每 tick 若 actor 有未完成移动则继续走，到达后才可执行该行为。

### 5.4 观察（observe）

- 系统原语行为，**不可删除**（可在面板调冷却与权重）：花 1 tick 观察当前或某个相邻环境 →
  - 揭示该环境：名称/类型/描述 + 内部人物名单 + 物品清单；
  - 写入知识（`knowledge.observedAt`），并产生一条叙事价值高的低权重事件「X 在 Y 张望」。
- 观察是**探索类欲望的主要满足通道**（见 5.6），也是作者「让场面动起来」的保底动作：什么都不定义时，人物会自动张望与走动。

### 5.5 交互

- 同环境、互见（直接感知层）的人物之间才能发生 `requireCompanion` 行为；目标选择 = 同环境互见者里「与本次行为相关欲望强度最高」的那个。
- 互动的结果在行为层：行为的正 `desireEffects` 同时作用于目标（「挑衅」加剧对方愤怒）——人物间耦合与冲突链的机制。

### 5.6 新颖度信号（探索欲的数值来源）

```ts
export interface SimKnowledge {
  /** 已到过或观察过的环境 */
  knownEnvIds: string[];
  /** 已见过的人物 */
  knownActorIds: string[];
  /** 最近观察 tick（用于「记忆已过时」判定） */
  observedAt: Record<string, number>;
}
```

每 tick 引擎结算 `novelty: Record<desireId, number>`：本 tick 新到达的环境 + 新观察到的人物/环境 → 对声明 `satisfiedBy:'novelty'` 的欲望按 `noveltyRelief`（默认 25/次）缓解。这是「探索欲」不必依赖作者写行为即可闭环的关键——世界模型提供「未知的量」，欲望层只声明「未知让我满足」。

### 5.7 空 schema 兜底

没有任何作品欲望/行为定义时，引擎以 `idleWeight`（默认 1）驱动原语：**观察当前位置 → 走向一个未到过的环境 → 再观察**。意义：作品可以「先跑起来再调参」，事件日志永远有内容；数值架构师也可以基于「空跑 20 tick 的日志」再给出针对性建议。

### 5.8 常量与调参边界

`PERCEPT_RANGE / SPEED / ARRIVE_EPS / OBSERVE_COOLDOWN / NOVELTY_RELIEF / IDLE_WEIGHT` 均为引擎常量，面板「世界模型」页**只读展示**（附说明），v1 不开放编辑——避免作者陷入「调引擎」而不是「调欲望」。开放为作品级可调项留 v2。

## 6. 欲望层 L2 与行为层 L1（作品级）

### 6.1 总原则

> **作品的一切叙事需求，都翻译成「某个人物在某种条件下产生某种欲望」。**

这句话既是给作者的创作方法，也是数值架构师系统提示的第一条。欲望是唯一驱动力来源；行为了是欲望的满足手段；世界模型提供满足所需的物理条件。

### 6.2 欲望分类法（架构师建议模板，不强制）

| 类别 | 典型欲望 | 建议增长 / 阈值 | 世界信号耦合 |
| --- | --- | --- | --- |
| 生理 | 生存欲、饥饿、休息欲、恐惧 | 增长 0.6-1.0 / 阈值 60-80 | 属性门槛（体力/理智）、环境安全度 |
| 社会 | 爱情欲、归属欲、权力欲、认同欲 | 增长 0.8-1.2 / 阈值 50-70 | 同环境人物属性、关系文本 |
| 认知 | **探索欲**、求知欲 | 增长 0.5-0.8 / 阈值 40-60，`satisfiedBy:'novelty'` | 新颖度信号（5.6） |
| 情感 | 复仇欲、怜悯欲、执念 | 增长 1.0-1.5 / 阈值 65-85 | 目标人物在场、记忆过时 |

### 6.3 数据模型

```ts
export interface SimPlaySchema {
  version: 1;
  attributes: SimAttributeDef[];   // 扩展属性：可行性门槛与消耗（体力/理智/灵力…）
  desires: SimDesireDef[];         // 欲望全集（作品级调色板）
```

## 7. 数值节拍引擎

新文件 `src/engines/simPlayEngine.ts`，**全部纯函数**（输入状态输出状态，不碰 store、不碰 React），由 store 外的定时循环驱动 `step()`，按批写回。

### 7.1 tick 流程（每 actor，按 characterId 排序保证复现）

1. **位置结算**：按几何重算 `envId`；若在移动中则推进 `SPEED`，到达则记录「到达」事件与新环境。
2. **感知更新**：计算直接感知名单（同环境 + 距离）与环境感知；更新 `knowledge`。
3. **新颖度结算**：新环境/新面孔 → `novelty` 累计（供 `satisfiedBy:'novelty'` 欲望缓解）。
4. **欲望演化**：`intensity = clamp(intensity + growthPerTick, 0, max)`；novelty 满足者同时应用 `noveltyRelief`。
5. **冷却递减**；**移动中则跳过决策**（到达后再决策）。
6. **决策**：§7.2 评分，选出最高分行为；无可用行为则原语兜底（观察/走动）。
7. **执行**：应用 effects（clamp）→ 写 `SimEvent` → 设冷却 → 记录移动意图 → 正效果传播给同环境目标。
8. **事件剪枝**：`events` 环形上限 500，最旧截断（已叙事化的内容在脚本里）。

### 7.2 效用评分

```
score(b) = Σ_d [ intensity(d) × max(0, −effect_b(d)) ]      // 欲望越强、缓解越多越有吸引力
         + Σ_n [ intensity(n) × noveltyRelief × noveltyHit_b ]  // novelty 型欲望：观察/去未知环境有分
         × feasibility(b)                                   // 属性门槛 × 场地 × solo/companion × 移动可达
         × weight(b) × cooldownGate(b) × noise              // 冷却中=0；noise∈[0.9,1.1] seeded
```

- 属性在 v1 **只做门槛与消耗**，不进效用（避免双系统打架）：「体力耗尽 → 不可行动 → 只能休息」由门槛达成。
- 加剧型行为（正效果项）不直接产生效用，靠 `weight` 与传播制造剧情。
- **可复现**：`mulberry32(seed)`，按 `(tick, actorId)` 派生子种子；同 seed + 同 schema + 同初始态 = 逐 tick 一致的事件链（测试硬断言）。

### 7.3 涌现从哪来

| 机制 | 设计着力点 |
| --- | --- |
| 欲望冲突 → 摇摆 | 至少一对欲望在行为效果上互斥（满足 A 加剧 B），人物在两者间来回 |
| 世界信号 → 自发行动 | 探索欲 × 未知环境 = 自主游荡；生存欲 × 低体力 = 回家休息 |
| 条件行为 → 爆发点 | 门槛行为（需要床/需要仇敌在场）不可用时走保底，条件满足即爆发 |
| 阈值错拍 | 各欲望 `threshold` 错开 ≥20%，全场不同时进入主导状态 |
| 互动传播 | 加剧行为把欲望传染给同环境目标，单人物冲动演化为多人冲突链 |
| 记忆过时 | 知识里的名单可能已过时 → 人物按旧印象行动（戏剧性错误） |
| 冷却节奏 | 冷却长短本身是节奏设计，防止单行为刷屏 |

### 7.4 运行模式

- **自动**：定时循环，间隔 0.5s / 1s / 2s / 5s 可调，暂停 / 继续。
- **手动单步**：「下一步」按钮调同一个 `step()`——推演即调试，作者逐拍观察。
- 两模式共用引擎，都做（决策 D9）。

## 8. LLM 叙事化层

新文件 `src/engines/simNarrator.ts`。**只读数值世界，不回写数值**（单向流）。

- **批量粒度**（决策 D6）：不逐 tick 调用。每次取 8-12 个事件（或用户框选范围）打包：事件序列（含主导欲望）+ 涉及人物卡（basicInfo/identityInfo/relations 截断 + 当前欲望）+ 环境路径 → 单次调用产出叙事。
- 系统提示要求：逐事件覆盖（每个事件都要在文中按序呈现）、主导欲望转译为心理与节奏（不出现「复仇 72/100」裸数值）、环境用真实路径、不得新增事件或改变结果。
- 产出回填 `SimEvent.narrated` 与 `PlotScript.narrative`；失败可重试，重试不改变事件。
- **导演干预 v1**：暂停态下——① 调某人物某欲望强度；② 强制某人物下一 tick 执行指定行为；两者都产生 `manual` 标记事件，叙事化一并覆盖。任意事件注入留 v2。

## 11. 系统级技能：数值架构师

### 11.1 定位

**不进用户写作技能库**（`nc2-writing-skills-v1` 无内置条目是刻意设计）。形态照 `memoryTemplates` 先例：系统内置规范 = 推演面板「AI 构建设计」按钮的系统提示 + 专用产出协议块。它回答：**这个作品该有哪些欲望、哪些行为、数值怎么配，跑起来才有戏看。**

### 11.2 输入与产出协议

输入（自动收集）：全文目标/规则摘要、人物库摘要（姓名/性别/身份/关系，截断）、舞台环境类型统计、题材提示（用户输入，可选）、**空跑 20 tick 的事件日志**（可选——先跑再设计，诊断式建议）。

产出协议块【推演设计】（逐行结构化 → 校验器 → 草稿-确认制渲染，用户逐块确认才写入 schema）：

```
【推演设计】
属性｜体力｜0-100｜默认 80｜耗尽只能休息
欲望｜探索欲｜认知｜0-100｜默认 40｜增长 0.7/拍｜阈值 55｜新颖度满足｜对未知环境好奇
欲望｜复仇｜情感｜0-100｜默认 20｜增长 1.2/拍｜阈值 65｜目睹仇敌或提及旧怨时增长，公开清算后缓解
行为｜摊牌｜当众挑明恩怨｜复仇-35｜安全-15｜需同伴｜冷却 8
行为｜寻访｜去没去过的地方看看｜探索欲-20｜冷却 2｜走向未知环境
行为｜休息｜找个地方恢复体力｜体力+30｜需 房间/床｜冷却 3
行为｜闲逛｜四处走动观察｜无门槛保底｜冷却 2
指派｜李刚｜复仇 70、探索 20
…
```

### 11.3 设计准则（系统提示硬性要求）

1. 欲望 3-5 个，至少一对张力对（满足其一加剧另一）。
2. 每个欲望至少 2 个满足行为（不同场地或条件），避免单一解。
3. 至少 1 个阈值属性做可行性门槛。
4. 各欲望 `threshold` 错开 ≥20%。
5. 单行为对单欲望缓解量 20-40，不允许一拍清空。
6. 必须有 2-3 个无门槛保底行为。
7. 至少 2 个行为依赖他人在场，制造人物间耦合。
8. `growthPerTick` 按目标节奏反推：正常节奏下 20-40 tick 触发一次主导欲望。
9. 探索类欲望标 `satisfiedBy:'novelty'`，不要用行为硬凑。

### 11.4 本地校验器 validateSchema

LLM 产出先过纯函数校验器再渲染确认块：

- **errors**（阻断）：引用完整性（effects/门槛指向的 ID 存在）、数值域（min<max、default∈[min,max]）、ID 唯一、指派引用的欲望存在。
- **warnings**（黄条，不阻断）：违反 §11.3 各准则（无张力对 / 无保底行为 / 阈值未错开 / 某欲望无满足行为 / 探索类未用 novelty…）。
- 面板常驻显示 warnings——数值平衡是持续状态，不是一次性检查。

## 16. 风险与应对

1. **叙事与事件脱节** → 系统提示强制逐事件覆盖；UI 按事件数核对并提示缺失。
2. **数值失衡（全员只做一件事）** → validateSchema 准则警告 + 行为分布统计实时可见 + §7.3 调参表。
3. **世界模型过度工程** → 严格锁死 v1 边界：无寻路、无墙门、无障碍、无昼夜；常量只读。
4. **舞台与卷画布割裂/重复劳动** → 「从卷画布复制布局到舞台」一键镜像；文档明确舞台=沙盒、卷=成书舞台。
5. **会话与人物库漂移** → `stateFingerprint` 校验 + 恢复时提示重置。
6. **性能** → 引擎在 store 外循环、按批写回；决策复杂度 O(actors×behaviors) 可忽略；日志环形 500。
7. **正文上下文膨胀** → 【剧情脚本】cap 2400 + 槽位上限 2 + 已删脚本忽略。
8. **复杂度蔓延** → v1 明确不做：寻路、多舞台并发、关系数值化、故事内时钟（tick 是抽象节拍）、任意事件注入、推演写回画布/人物库、agent 向舞台投放。

## 18. 一句话备忘

剧情推演模拟器 = 作品内固定的舞台画布（沙盒，同卷画布并列，可从卷画布一键镜像布局）+ 系统内置世界模型（空间/感知/移动/观察/交互 + 新颖度信号，不可编辑）+ 作品级欲望层（一切叙事需求翻译成人物的欲望）与行为层（欲望的满足手段）+ 本地 seeded 节拍引擎按效用决策驱动在场人物行动涌现事件链 + LLM 低频批量叙事化 + 指定主视角的事件链沉淀为剧情脚本库 + 章节槽位引用后以【剧情脚本】既定事件块注入正文生成——空 schema 也能先跑、可复现、与自上而下流程并行互补。
