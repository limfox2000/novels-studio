# 编辑技能记忆 · 基础模板

八个生成能力模块各一份记忆模板，文件名序号与 `EDITOR_MODULES` 顺序一致（全文目标/全文规则/人物生成/环境生成/章节大纲规则/章节需求/卷生成/正文生成）。约定：

- **模板文件只留骨架与用途**：H2 小节 + 斜体说明行（用途指引，永久保留）；填写规则写在记忆更新器里（`meetingEngine.ts` 的 `MEMORY_UPDATE_RULES` 为总规则，integrate/optimize 共用），模板文件保持干净。
- **模板 = 出厂即可用的 skill**：每个小节自带基线条目（出厂写法），未填充任何记忆时也能独立产出该能力的结构化内容；调教记忆只追加在基线之下，更新器不改写、不删除基线条目（与 pristine 模板逐行比对识别）。
- **有固定构成的模块，小节镜像其可调部分**（当前：01-全文目标三点构成 = 题材/主线/爽点预期；02-全文规则两部分 = 世界观规则/写作文风；03-人物生成四段 = 基础属性/基础信息/身份信息/人物关系；04-环境生成三段 = 外观/功能/氛围——名字/类型是节点字段，镜像环境设定块的描述构成；05-章节大纲规则五段可调部分；06-章节需求三段 = 主线推进/核心事件与人物/期待感——需求默认由创作者输入，编辑只代拟；07-卷生成三段 = 主线推进/核心事件与人物/期待感——与章节需求同构、高一层，卷介绍是整卷章节需求的依据；08-正文生成五段技法 = 开篇与入戏/描写技法/对话写法/节奏与张弛/过渡与章尾收束——剧情以章节大纲为准、文风口径以全文规则为准，只沉淀写作技法）：结构与输出契约定格在「结构（固定契约）」小节，结构本身不因调教改动；可变性决定沉淀深度——纯结构段零记忆、主手法段为主沉淀区、标准段只留一个标准。
- **记忆更新器职责**：新增记忆按内容归类到最匹配的小节（对话协议要求先写「## 小节名」再列条目），条目写在基线之下；每条一行、以「- 」开头、正向表述、脱离对话可读，拿不准归属的宁可不记。实现：`src/engines/memoryTemplates.ts`——`parseSectionDraft` 归类校验、`appendToSkillCopy` 确定性追加、`revalidateSkillCopy` 重建式校验（骨架行由模板原样补齐：被改写/删除/挪动的基线自动复原，调教条目再过否定/残留过滤）、`trimSkillCopy` 保骨架截断；更新器总规则在 `meetingEngine.ts` 的 `MEMORY_UPDATE_RULES`（integrate/optimize 共用）。
- **每位编辑的记忆 = 模板的一份填好副本**：编辑创建时八个模块各复制一份模板全文（`blankSkillMemories`），存进该编辑的 `skills` 槽位；空小节只保留说明行，调教记忆追加在基线之下，空副本（被手动清空）在吸收时按模板重新铺底。
- frontmatter `kind: editor-memory`；放在 `skills/` 子目录，不会被 server.py 的脚本技能注入读到（`_builtin_skills` 只扫顶层 `*.md`）。
